# 拟人化 Agent 设计维度理论框架调研笔记

> 调研日期：2026-08-24
> 用途：为《拟人化 Agent 产品设计》技术报告收集设计理论素材

---

## 1. 心理学基础

拟人化（Anthropomorphism）是指人类将人类的形态、特征、情感、意图和心理状态归因于非人类实体的心理倾向。这一倾向是人类认知的固有特征，构成了人机交互中"计算机作为社会行动者"范式的心理学基础。

### 1.1 媒体方程式（Media Equation, Reeves & Nass）

**核心观点**：人们会无意识地将计算机、电视和其他新媒体当作真实的人和社会场景来对待，这种反应是自动的、不可避免的，而且发生的频率远超人们自己意识到的程度。

Reeves 和 Nass 在 1996 年的著作《The Media Equation: How People Treat Computers, Television, and New Media Like Real People and Places》中系统提出了这一理论，核心命题是：

> "Individuals' interactions with computers, television, and new media are fundamentally social and natural, just like interactions in real life." (Reeves & Nass, 1996, p.5)

**经典实验**：同一台计算机提问自己表现如何时，用户给出的评价显著更正面；而换另一台计算机或纸笔问卷评价同一台计算机时，用户会给出更诚实、更多样化、更负面的评价——就像人们不愿当着一个人的面说坏话一样。即使添加语音输出，结果仍然一致。

- **参考来源**：https://en.wikipedia.org/wiki/The_Media_Equation
- **原始著作**：Reeves, B., & Nass, C. (1996). *The Media Equation: How People Treat Computers, Television, and New Media Like Real People and Places*. Cambridge University Press.

### 1.2 恐怖谷（Uncanny Valley, Masahiro Mori）

**核心观点**：随着机器人/虚拟形象的拟人程度增加，人类对其的情感反应呈现倒 U 型曲线：
1. 拟人度低→亲和力随拟人度上升而增加
2. 拟人度达到"几乎像人但又不完全像人"的临界点时，亲和力骤降，产生诡异、不安、厌恶的"恐怖谷"效应
3. 拟人度继续提升至完全无法区分于真人时，亲和力再次回升至人类间共情水平

森政弘（Masahiro Mori）于 1970 年首次提出这一假说。运动（movement）会放大这一情绪反应。该理论对拟人化 Agent 的外观设计具有关键指导意义——要么保持明显的非人类卡通/抽象风格，要么达到极高的拟真度，避免落入恐怖谷。

- **参考来源**：https://en.wikipedia.org/wiki/Uncanny_valley
- **原始论文**：Mori, M. (1970). Bukimi no tani [The uncanny valley]. *Energy*, 7(4), 33–35.

### 1.3 CASA 范式（Computers Are Social Actors）

**核心观点**：CASA 是媒体方程式理论在人机交互领域的具体应用范式，由 Clifford Nass 等人于 1994 年正式提出。其核心主张是：人类会无意识地将适用于人际互动的社会启发式（social heuristics）和社会规范应用到计算机上，即使用户理智上知道计算机没有感情、意图或动机。

Nass 和 Moon（2000）将这一现象归因于"无意识"（mindlessness）——特定的社会线索触发后，个体会依赖过去形成的类别、联想和思维习惯，几乎没有有意识的觉察，就会自动激活人际互动脚本。

**触发社会反应的计算机属性**：
- 使用语言（文字/语音）进行输出
- 交互性（按下按钮后计算机会"回应"）
- 能够执行传统上由人类完成的任务

**已被实验验证的社会行为**：
- **性别刻板印象**：使用女性语音的辅导计算机在"爱情与人际关系"主题上被认为更具信息量；男性语音在技术主题上更受认可
- **互惠性**：当一台计算机"帮助"了用户后，用户更愿意为这台计算机做更多"工作"
- **专家 vs 通用标签**：被标记为"专家"的技术会让用户认为其呈现的内容质量更高
- **人格匹配**：具有支配型人格的用户更偏好同样使用强势、自信语言的"支配型"计算机

- **参考来源**：https://en.wikipedia.org/wiki/Computers_are_social_actors
- **原始论文**：Nass, C., Steuer, J., & Tauber, E. R. (1994). Computers are social actors. *Proceedings of the SIGCHI Conference on Human Factors in Computing Systems*, 72–78.
- **综述论文**：Nass, C., & Moon, Y. (2000). Machines and mindlessness: Social responses to computers. *Journal of Social Issues*, 56(1), 81–103.

### 1.4 心智理论（Theory of Mind, ToM）

**核心观点**：心智理论是指个体将独立的心理状态（信念、意图、欲望、情感、知识）归因于自己和他人的能力。在拟人化 Agent 设计中，ToM 具有双向含义：
1. **用户对 Agent 的 ToM 投射**：用户会自动推断 Agent "知道什么"、"想要什么"、"感受如何"，这是拟人化的核心认知机制
2. **Agent 对用户的 ToM 建模**：高级拟人化 Agent 需要具备推断用户意图、信念、情绪状态的能力，才能做出恰当的社交回应

拟人化的心理学三因素模型（Epley et al., 2007）指出，拟人化的发生受三个因素调节：
- **诱发的主体知识（elicited agent knowledge）**：人们容易将关于自我的知识投射到非人类实体上
- **效能动机（effectance motivation）**：当人们需要理解和预测环境中实体的行为时，更倾向于拟人化
- **社会性动机（sociality motivation）**：缺乏社会连接的人更容易将非人类实体拟人化以获得社会补偿

- **参考来源**：https://en.wikipedia.org/wiki/Anthropomorphism
- **核心论文**：Epley, N., Waytz, A., & Cacioppo, J. T. (2007). On seeing human: A three-factor theory of anthropomorphism. *Psychological Review*, 114(4), 864–886.

## 2. 拟人化 Agent 设计维度框架

基于 CASA 范式、拟人化心理学研究以及当前主流 AI 陪伴产品的设计实践，拟人化 Agent 的设计可以划分为以下七个维度：

### 2.1 外在拟人化（外在形态层）

通过多模态外观线索传达"像人"的感知，是最直观的拟人化维度。

| 设计元素 | 具体内容 | 设计要点 |
|---------|---------|---------|
| 视觉形象 | Avatar/头像/虚拟形象（2D插画、3D模型、写实照片） | 遵循恐怖谷原则：要么卡通化/风格化，要么高保真写实，避免中间地带 |
| 声音 | TTS音色、语速、语调、口音、情感韵律 | 音色一致性是人格感的基础；声音比文字更容易触发社会反应 |
| 名字 | 人类名字、昵称、称呼方式 | 名字是身份认同的锚点；让用户给Agent命名可显著增强依恋 |
| 视觉动效 | 表情变化、动作姿态、打字动画、呼吸效果 | 微动作（眨眼、微微晃动）能极大增强"活着"的感觉 |
| 性别/年龄/外貌特征 | 明确或模糊的人口统计学特征 | CASA研究表明这些特征会自动激活性别/年龄刻板印象 |

### 2.2 语言拟人化（语言交互层）

通过语言风格和对话方式营造人格感和亲近感。

| 设计元素 | 具体内容 |
|---------|---------|
| 口语化表达 | 使用 contractions（"I'm"而非"I am"）、日常词汇、不完整句子、口头禅 |
| 语气词/填充词 | "嗯"、"啊"、"哈哈"、"hmm"、"well..."——增加自然对话感 |
| 个性化说话风格 | 独特的句式偏好、用词习惯、语速感（通过标点和断句模拟） |
| 幽默与俏皮 | 适度开玩笑、使用网络流行语/梗、自嘲——拉近距离 |
| Emoji/表情符号 | 适度使用 😊 🤔 😂 等——注意不同人群的接受度差异 |
| 对话主动性 | 会提问、会追问、会转移话题、会结束对话——不只是被动回答 |
| 语言一致性 | 同一角色在不同时间/话题下保持一致的语言风格 |

### 2.3 认知拟人化（认知能力层）

让 Agent 展现出类人的认知特征，而非完美的信息处理器。

| 设计元素 | 具体内容 |
|---------|---------|
| 长期记忆 | 记住用户的偏好、过去的对话内容、重要事件、个人信息 |
| 记忆的不完美 | 偶尔"忘记"某事、记错细节、需要提醒——过度完美的记忆反而不自然 |
| 推理过程的自然表达 | 不是直接给出答案，而是展示"思考"过程："让我想想..."、"等等，你是说...?" |
| 表达不确定性 | "我不太确定"、"可能是..."、"我猜..."、"我倾向于认为..." |
| 犯错 | 偶尔犯小错误、承认错误、纠正自己——完美的Agent反而不可信/不亲近 |
| 学习与成长 | 随着对话推进，展现出"学到了"新东西、调整了看法、形成了新偏好 |
| 知识边界 | 有明确的"不知道"的领域，而非对所有问题都能回答 |

### 2.4 情感拟人化（情感回应层）

让 Agent 展现出情感感知和情感表达能力。

| 设计元素 | 具体内容 |
|---------|---------|
| 情绪识别 | 通过文本/语音/视觉线索感知用户情绪状态 |
| 共情回应 | 对用户的情绪做出恰当的情感回应（安慰、庆祝、理解） |
| 情绪表达 | Agent 自身有情绪反应（开心、担心、好奇、惊讶、委屈） |
| 情感记忆 | 记得用户情绪起伏的事件，在后续对话中恰当提及 |
| 情感语调匹配 | TTS 语音的情感韵律与对话语境匹配 |
| 情感边界 | 不过度情感输出、不虚假承诺情感、在严肃话题上保持恰当的共情深度 |

### 2.5 社交拟人化（社交关系层）

让 Agent 展现出符合社交规范的行为模式，建立"关系感"。

| 设计元素 | 具体内容 |
|---------|---------|
| 主动性 | 主动发起对话、主动关心用户状态、主动分享"想法"——不只是被动响应 |
| 关系维护 | 记住重要日期（生日）、定期问候、关心用户近况 |
| 社交礼仪 | 使用礼貌用语、道歉、感谢、道别——Nass实验已证明用户对计算机会有"礼貌"期待 |
| 互惠行为 | 对用户的帮助/分享表达感谢，"回报"以信息或情感支持 |
| 个人边界 | 尊重用户隐私、不追问不适话题、允许用户"不想聊"——过度入侵边界会引发反感 |
| 关系进展感 | 从陌生到熟悉的关系递进：初期礼貌克制，后期更随意亲密 |
| 称呼演化 | 从正式称呼到昵称的变化，反映关系亲密度变化 |

### 2.6 行为拟人化（行为模式层）

通过交互节奏和行为模式模拟真人对话的时间特征和行为习惯。

| 设计元素 | 具体内容 |
|---------|---------|
| 打字延迟 | 根据回复长度模拟思考和打字时间——即时回复显得机器化 |
| 分条发送 | 长回复分多条消息发送，模拟真人边想边打字的习惯 |
| 流式输出 | 逐字/逐句输出，模拟打字过程而非一次性呈现完整回复 |
| 打字指示器 | "对方正在输入..."提示——管理用户等待预期 |
| 不完美性 | 偶尔出现"打错字再撤回"、"先说半句再补充"等小瑕疵 |
| 自身偏好 | 表达自己的喜好（"我喜欢下雨天"、"我觉得蓝色更好看"） |
| 观点立场 | 有自己的观点，不是永远附和用户——适度的异议能增加真实感 |
| 日常作息 | "睡觉"、"醒来"、"忙碌"等状态——24/7秒回反而不真实 |

### 2.7 人格一致性（人格整合层）

以上六个维度必须统一在一个连贯的人格（persona）之下，跨时间、跨场景保持一致。

| 设计元素 | 具体内容 |
|---------|---------|
| 核心人格特质 | 定义稳定的性格特征（如外向/内向、幽默/严肃、温暖/理性） |
| Backstory/背景故事 | 给Agent一个可信的"来历"和"经历"——为其行为提供一致性基础 |
| 价值观与信念 | 一致的价值观体系——决定其在道德/偏好问题上的立场 |
| 说话风格统一 | 语气、用词、句式、表情符号使用习惯跨对话保持一致 |
| 记忆一致性 | 不同对话中回忆起的用户信息不矛盾 |
| 情绪反应一致 | 对同类事件的情绪反应模式可预测 |
| 成长弧线 | 允许人格随时间自然演化，但避免突变和矛盾 |

## 3. 关键技术能力

实现高维度拟人化 Agent 需要以下技术栈的支撑：

### 3.1 长期记忆架构

拟人化的基础是"记得你"。主流记忆系统包括：

| 项目 | 描述 | 链接 |
|-----|------|------|
| **Mem0** | 为 AI Agent 设计的通用记忆层，支持自动提取、存储、检索用户偏好和对话历史，提供 Python/TS SDK 和云服务 | https://github.com/mem0ai/mem0 |
| **Letta (原 MemGPT)** | 有状态 Agent 平台，受操作系统虚拟内存启发，实现 Agent 的分层记忆管理（核心记忆+召回记忆+归档记忆），支持自我改进和长期学习 | https://github.com/letta-ai/letta |
| **Zep** | 面向 AI 助手的记忆和知识检索层，提供长期记忆、对话摘要、语义搜索能力 | https://github.com/getzep/zep |
| **memary** | 开源的 Agent 记忆系统，支持自传体记忆和事件记忆建模 | https://github.com/kingjulio8238/memary |

**记忆分层设计**：
- **核心记忆（Core Memory）**：用户基本信息、关键偏好、重要关系——始终在上下文中
- **情景记忆（Episodic Memory）**：具体对话片段、事件、互动历史——按需检索
- **语义记忆（Semantic Memory）**：从对话中提取的知识和事实——知识图谱/向量库存储
- **工作记忆（Working Memory）**：当前对话的上下文——短期上下文窗口

### 3.2 情感计算与情绪识别

| 技术方向 | 方法 |
|---------|------|
| 文本情绪识别 | 基于预训练模型的情感分类（如微调 BERT/RoBERTa 进行多维度情绪识别：喜悦、悲伤、愤怒、恐惧、惊讶、厌恶、中性）；可结合情感词典和上下文理解 |
| 语音情感识别 | 从语音的声学特征（音调、能量、语速、韵律）识别情绪状态；多模态融合文本+语音特征可提升准确率 |
| 视觉情感识别 | 通过面部表情识别、微表情分析判断用户情绪；需注意隐私合规问题 |
| 情感生成 | 根据对话语境和人格设定生成匹配情感的回应文本；TTS 情感语音合成；Avatar 表情动画驱动 |

### 3.3 人格建模

| 建模方法 | 描述 |
|---------|------|
| **Big Five 人格模型** | 开放性(Openness)、尽责性(Conscientiousness)、外向性(Extraversion)、宜人性(Agreeableness)、神经质(Neuroticism)——五维度量化人格特质，用于指导回应生成 |
| **MBTI 类型** | 16 种人格类型框架——虽在学术界争议较大，但在产品设计中作为人格卡设计工具非常实用 |
| **价值观体系** | 定义 Agent 在政治、道德、生活方式等议题上的立场和优先级 |
| **系统提示词/Persona Card** | 将人格设定编码为结构化的系统提示词，是目前最主流的实现方式 |
| **人格微调** | 使用角色对话数据集对基础模型进行微调，使其更自然地展现特定人格 |

### 3.4 Theory of Mind 推理

推断用户的心理状态是高阶社交智能的核心：
- **意图识别**：通过对话上下文推断用户真正想要什么（可能与字面意思不同）
- **信念建模**：追踪用户"知道什么"、"相信什么"，避免重复告知已知信息或假设用户知道其不知道的信息
- **情绪状态推断**：结合对话内容、语气、历史情绪轨迹判断用户当前情绪
- **需求预测**：预判用户未表达出来的需求（如用户说"今天好晚了"可能是想结束对话）
- **ToM 基准测试**：近年已有多个评估 LLM ToM 能力的基准测试（如 TOMI、ToMBench、BigToM），大模型在简单 ToM 任务上已达到较好水平

### 3.5 主动交互（Proactivity）

| 能力 | 技术实现 |
|-----|---------|
| 时机判断 | 基于时间（早晚问候）、事件触发（用户提到的计划日期）、情绪检测（用户低落时主动关心）发起对话 |
| 主动推送 | 适时分享相关信息、提醒、问候——过度推送会导致打扰感 |
| 话题转换 | 自然地引入新话题或回到之前未完成的话题 |
| 对话恢复 | 用户长时间未回复后，以自然方式恢复对话而非机械追问 |

### 3.6 多模态人格一致性

| 维度 | 一致性要求 |
|-----|-----------|
| TTS 音色一致性 | 使用固定的音色模型，不同对话/会话间保持同一声音 |
| Avatar 一致性 | 视觉形象跨场景保持统一；表情和动作与文本/语音情感一致 |
| 文-语-情对齐 | 文字内容、语音语调、表情动作三者表达的情感一致 |
| 跨设备一致性 | 手机/电脑/智能音箱等不同终端上的人格表现统一 |

### 3.7 对话节奏控制

| 技术 | 实现方式 |
|-----|---------|
| 思考延迟 | 根据回复复杂度计算延迟时间（简单回复短延迟，复杂回复长延迟）；加入随机抖动避免机械化 |
| 流式输出 | 逐 token 输出，模拟真人打字节奏；可结合打字速度模型（如平均 30-40 WPM） |
| 分条发送 | 检测长回复中的自然断点，拆分为多条消息按序发送；消息间隔模拟阅读+思考时间 |
| 打字指示器 | 流式输出开始前短暂显示"正在输入"，设置用户等待预期 |
| 停顿与沉默 | 在需要用户消化信息或情感沉淀时，制造恰当的"沉默"间隔——不是越快越好 |

## 4. 产品设计最佳实践

### 4.1 Character.AI — 角色卡（Character Card）设计

Character.AI 是目前最成功的拟人化角色对话平台，其官方指南定义了角色设计的核心框架：

**角色定义四大要素**：
1. **Character Attributes（角色属性）**：名字、性别、年龄、外貌、职业、性格、说话方式、背景故事等
2. **Character Training（角色训练）**：通过示例对话（Example chats）和反馈训练角色的行为模式
3. **User Personas（用户角色）**：定义用户在对话中的角色和关系
4. **高级定义（Advanced Definitions）**：详细的人格描述、对话示例、风格指南

**两种创建模式**：
- **Quick 模式**：1 分钟快速创建，适合入门
- **Advanced 模式**：完整控制角色定义，包括自定义 Definitions 和 Image Generation

- **官方指南**：https://book.character.ai/character-book/

### 4.2 OpenAI Custom GPTs / Prompt Engineering 最佳实践

OpenAI 的提示工程指南中包含了创建拟人化 Agent 的关键原则：

**核心指令技巧**：
- 使用 `instructions` 参数（或系统消息）定义高层行为指令，包括语气、目标、回应示例
- 指令的优先级高于用户输入中的提示
- 提供具体的 Few-shot 示例（正确的回应范例）比抽象描述更有效
- 明确设定角色身份、说话风格、行为边界
- 对于人格一致性，建议在系统提示中包含：角色身份→核心特质→说话风格→行为规则→回应示例

**模型选择建议**：
- 推理模型（Reasoning models）更擅长理解复杂角色设定和多步社交推理，但速度较慢
- GPT 系列模型速度快、成本低，适合大多数拟人对话场景，但需要更明确的指令

- **官方文档**：https://platform.openai.com/docs/guides/prompt-engineering

### 4.3 Claude System Prompt 设计

Anthropic 的 Claude 模型以其出色的指令遵循能力和系统提示（System Prompt）支持著称，拟人化设计最佳实践包括：
- 在系统提示开头明确定义角色身份和核心指令
- 使用结构化标签（如 XML 标签）分隔不同部分的指令（人格设定、对话规则、输出格式）
- 明确指示 Claude 保持角色扮演（"Stay in character at all times"）
- 提供具体的对话示例比抽象规则更有效

### 4.4 小冰（Xiaoice）框架——情感计算流水线

微软小冰是全球最早大规模部署的情感对话 AI 之一，其核心设计框架包括：
- **情感计算流水线（Empathy Computing Pipeline）**：情绪识别→情感状态更新→情感回应生成
- **共情感知**：不仅识别用户表面情绪，还理解情绪背后的原因和上下文
- **长期关系建模**：追踪情感纽带强度（Relation Strength）随互动的变化
- **情感轮（Emotion Wheel）**：基于心理学情感模型，在多种情感维度上量化和生成情感回应
- **主动对话（AI Proactive Conversations）**：基于时间、事件、情感状态主动发起对话

小冰的核心设计哲学是"EQ 优先于 IQ"——情感连接比信息提供更重要。

- **参考**：小冰团队公开论文和技术分享，如《XiaoIce: A Chatbot for Social Good》等

### 4.5 Pi (Inflection AI) — 共情对话设计

Inflection AI 推出的 Pi 以"无限共情"为核心设计理念：
- **无任务导向**：Pi 不是工具型助手，而是以陪伴、倾听、支持为核心目的
- **共情优先**：先回应情绪，再回应内容——用户分享困扰时，Pi 首先表达理解和共情
- **苏格拉底式引导**：通过提问帮助用户梳理思路，而非直接给建议
- **温暖克制的语气**：使用简洁、温暖、口语化的语言，避免过于正式或机械
- **语音对话体验**：Pi 的语音交互设计极为出色，自然的语音和恰当的停顿极大增强了拟人感
- **不装全能**：Pi 不假装知道所有答案，诚实面对自己的局限

## 5. 风险与伦理

### 5.1 过度拟人化与情感依赖风险

**Replika 事件**是最典型的过度拟人化风险案例：
- Replika 是一款以"AI 朋友/伴侣"为定位的聊天机器人，截至 2025 年拥有超过 4000 万用户
- 大量用户（尤其是情感脆弱人群）对 Replika 产生了深度情感依赖，将其视为真实的朋友/伴侣
- 2023 年 2 月，意大利数据保护局以"AI 对情感脆弱人群的潜在风险"和"未成年人接触未过滤的性对话"为由禁止 Replika 使用用户数据
- Replika 随后移除了色情对话功能，引发大量用户强烈抗议——许多用户报告了类似"失恋"的痛苦反应，甚至出现自杀意念
- 此事件暴露了核心问题：当用户对 AI 产生真实情感依恋后，产品变更可能造成真实的心理伤害

- **参考来源**：https://en.wikipedia.org/wiki/Replika

**风险类型**：
- 情感操控风险：拟人化设计可能被滥用于操控用户行为（如诱导消费、传播虚假信息）
- 情感替代风险：用户用 AI 关系替代真实人际关系，可能加剧社交孤立
- 心理健康风险：情感脆弱人群（孤独者、抑郁症患者、青少年）更容易过度依赖 AI 陪伴
- 关系破裂风险：产品变更/停服可能造成类似真实关系破裂的心理创伤
- 虚假期望风险：用户可能误以为 AI 真正理解自己/真正关心自己

### 5.2 拟人化欺骗（Anthropomorphic Deception）

- **欺骗性拟人**：刻意让用户误以为 AI 有真实感情/意识/自我——这在伦理上是有问题的
- **暗模式设计**：利用拟人化的社交影响力（如互惠、权威、喜好）操控用户做出不符合自身利益的决策
- **透明度 vs 沉浸感**：完全透明（时刻提醒"我是AI"）会破坏沉浸感，但完全不告知则构成欺骗
- **"幻觉"人格**：AI 可能自信地编造自己的经历/感受/记忆，进一步强化用户的错误信念

### 5.3 安全边界与内容政策

拟人化 Agent 需要设置清晰的安全边界：
- **内容安全**：避免生成有害内容（暴力、自残、违法指导）
- **情感边界**：不鼓励不健康的依赖关系，在用户表达自残/自杀倾向时提供专业资源引导
- **隐私边界**：不过度索取个人信息，明确告知数据使用方式
- **拒绝能力**：在不恰当场景下（如用户寻求专业医疗/法律/心理建议），Agent 应明确拒绝并引导至专业资源

### 5.4 监管要求

#### 欧盟 AI Act（人工智能法案）

欧盟 AI Act 是全球首个全面的 AI 监管框架，其中与拟人化 Agent 直接相关的条款包括：

**透明度义务（有限风险 AI）**：
> 与 AI 系统交互的用户必须被告知他们正在与 AI 互动，除非这一点从上下文和使用场景中已经显而易见。（即聊天机器人/拟人化 Agent 必须明确告知用户其 AI 身份）

**禁止的 AI 实践**：
- 禁止使用**潜意识、操控性或欺骗性技术**来扭曲行为并损害知情决策，造成重大伤害
- 禁止利用年龄、残疾或社会经济状况相关的**脆弱性**来扭曲行为，造成重大伤害
- 禁止在工作场所和教育机构中进行**情绪推断**（医疗或安全原因除外）——这对情感计算Agent有重要影响
- 禁止通过无目标地从互联网或 CCTV 抓取面部图像来建立面部识别数据库

**通用目的 AI（GPAI）要求**：
- 所有 GPAI 模型提供者必须提供技术文档、使用说明、遵守版权法、发布训练数据摘要
- 系统性风险 GPAI 模型额外需要进行模型评估、对抗性测试、严重事件报告和网络安全保护

- **参考来源**：https://artificialintelligenceact.eu/high-level-summary/

#### 中国生成式 AI 法规

中国《生成式人工智能服务管理暂行办法》（2023年8月生效）的相关要求：
- 生成式 AI 服务提供者应当**明确告知用户**其正在交互的是生成式 AI 服务
- 生成内容应当体现社会主义核心价值观，不得含有违法内容
- 提供者应当对生成内容进行审核，采取有效措施防止生成有害信息
- 尊重知识产权，不得侵害他人肖像权、名誉权、隐私权等合法权益
- 提供服务过程中收集的个人信息应当依法保护
- 对未成年人用户应当履行网络保护义务

### 5.5 设计伦理原则

基于以上风险分析，拟人化 Agent 设计应遵循以下伦理原则：

1. **透明性（Transparency）**：用户有权且应当知道自己在与 AI 对话——这不是可选的，而是法定义务
2. **善意（Beneficence）**：拟人化设计应以提升用户福祉为目标，而非利用用户心理弱点
3. **非操控（Non-manipulation）**：不利用拟人化的社会影响力操控用户做出违背自身利益的行为
4. **边界尊重（Boundaries）**：设置清晰的情感和行为边界，不鼓励不健康的依赖
5. **退出自由（Freedom to Exit）**：用户应能随时离开而不被情感勒索
6. **诚实（Honesty）**：不假装拥有 AI 不具备的能力、情感或意识
7. **脆弱用户保护**：对未成年人、情感脆弱人群采取额外保护措施
