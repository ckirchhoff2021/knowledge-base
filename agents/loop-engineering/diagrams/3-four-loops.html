LEVEL 1

① 回合制

Turn-based
触发用户发一条 prompt
停止Claude 自判完成 / 需要更多上下文
原语普通对话 + SKILL.md 强化自验
适合不属于例行流程的短任务
人逐轮在场
LEVEL 2

② 目标循环

Goal-based
触发实时手动启动
停止目标达成 或 达到最大轮次；独立评估模型每轮检查
原语/goal
适合有可验证退出标准的任务
启动后人可走开
LEVEL 3

③ 定时循环

Time-based
触发指定时间间隔
停止人取消，或工作自然完结（PR 合并、队列空）
原语/loop 5m（本机）
/schedule（上云）
适合周期工作；对接外部系统（盯 PR/CI）
只看结果摘要
LEVEL 4

④ 主动循环

Proactive
触发事件或计划，全程无人实时参与
停止子任务达标即退；例程运行到被关闭
原语/schedule+/goal+Dynamic Workflows+Auto mode
适合源源不断的定义清晰工作：bug 分诊、迁移、依赖升级
on the loop 监督
官方 proactive 组合示例：/schedule every hour: check #project-feedback for bug reports.  /goal: don't stop until every report is triaged, actioned, and responded to.  修复时用 workflow 在并行 worktree 探索三个方案，再由 judge 对抗式评审。 成本控制：例行步骤路由给小/快模型，最强模型只用于关键判断。

分类看四件事

触发方式、停止条件、使用原语、任务类型——四类不是互斥功能，是自治度阶梯。

确定性目标最有效

"测试通过数、Lighthouse 阈值"让 Agent 无法过早自判完成；模糊目标要么永不停要么早停。

本机 vs 上云

/loop 在本机跑、关机即停；要关电脑后继续，就用 /schedule 把循环搬到云端例程。
