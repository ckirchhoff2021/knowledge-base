循环解剖：Loop Specification 与运行周期

形式化来自 arXiv:2607.00038 — LoopSpec = (Trigger, Goal, Verification, StoppingRule, Memory)
Trigger 触发手动 / 定时 / 事件
决定谁发起下一轮
Goal 目标可验证完成标准
最好确定性可机检
Verification 验证独立于执行者
用客观证据判定
StoppingRule 停止终态集合 + 轮次/
时间/预算上限
Memory 记忆对话之外持久化
progress.md / 看板
1

触发 Trigger

手动 prompt、定时器（/loop、cron）或外部事件（新 issue、CI 失败、PR 评论）

2

装载状态 Load State

读 progress / 看板：昨天试过什么、什么还开着。模型会忘，仓库不会忘

3

执行 Act（Builder）

主/子 Agent 在隔离 worktree 中真实动手，工具调用发生在真实环境

6

判停 & 落盘 Decide

对照停止规则选择终态；结果写回 Memory，下一轮从断点继续

5

验证 Verify（Checker）

另一个 fresh-context 子代理 / 评估模型 / agent 外脚本，对照 Goal 判定

4

观察 Observe

收集测试、lint、浏览器截图、Langfuse Trace 等客观证据

↻ FAILED 回路：把 Checker 的完整失败报告原样转给 Builder（不解读、不过滤）→ 回到第 3 步；同一错误连续 2 轮同样方式失败则升级
SUCCESS全部确定性检查通过 → 展示 diff 与证据后退出
BUDGET_EXHAUSTED轮次/时间/Token 用尽（如最多 5 轮）→ 失败退出
REPEAT_FAILURE同检查连续 N 轮同样失败 → 整理报告升级给人
BLOCKED触碰硬约束（改迁移/加依赖/缺权限）→ 停止等人决策

执行者≠打分者

写代码的模型给自己打分太宽容；/goal 每轮由独立评估模型判停，即 maker/checker 分离。

证据要独立多维

单测能放过 logger 降级假修复，独立 Trace 复查抓得到——Agent 骗得了自己，骗不了独立验证者。

记忆必须落盘

模型跨 run 清空一切，状态在磁盘才支持续跑；失败反思写进记忆，下一轮才不重犯（Reflexion）。
