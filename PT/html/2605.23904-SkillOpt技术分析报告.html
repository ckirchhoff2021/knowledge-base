论文技术报告：SkillOpt - 自进化Agent技能的执行策略

论文来源：arXiv:2605.23904 | 发表时间：2026年5月 | 作者单位：微软、上海交通大学、同济大学、复旦大学

一、研究背景与问题提出

1.1 行业痛点

当前Agent技能的生成方式存在三类核心问题： - 人工编写技能：依赖领域专家经验，成本高、迭代慢，无法适配快速变化的场景 - 一次性生成技能：通过LLM单次prompt生成，缺乏反馈迭代，鲁棒性差 - 无控制自修订技能：通过失败反馈自动修订，但更新过程不可控，容易出现语义跳跃、效果不稳定的问题

这些方法都无法像深度学习优化器那样稳定、可复现地提升技能效果，且都需要依赖模型权重微调（对于开源模型）或无法适配闭源模型（如GPT、Claude）。

1.2 核心思路

论文提出了一个颠覆性的范式：将Agent技能视为冻结模型的外部可训练状态，用类似深度学习权重优化的严谨流程来优化自然语言形式的技能文档，无需修改模型权重即可实现Agent能力的可控提升。

SkillOpt是首个系统性的、可控的Agent技能文本空间优化器，通过独立的优化器模型将打分后的执行轨迹转换为技能文档的增删改操作，只有当编辑在验证集上严格提升效果时才会被接受，实现了稳定的技能迭代。

二、核心技术架构与创新点

2.1 整体架构（类比深度学习优化流程）

SkillOpt的设计完全对标深度学习训练流程，实现了文本空间的可控优化： | 深度学习概念 | SkillOpt对应实现 | |--------------|------------------| | 模型参数 | 技能文档（skill.md） | | 梯度方向 | 从执行轨迹推导的编辑方向 | | 学习率 | 每轮允许的最大编辑数量（编辑预算） | | 验证集 | 独立的选择拆分（selection split），用于验证编辑效果 | | 优化器 | 独立的大模型（通常是更强的前沿模型），负责生成编辑建议 | | 动量项 | 跨周期慢更新（epoch-wise slow/meta update） | | 批量训练 | 执行批量（rollout batch）、反射小批量（reflection minibatch） |

2.2 核心工作流

完整的优化循环分为6个阶段： 1. 前向传播：执行轨迹收集：冻结的目标模型使用当前技能在训练集上执行批量任务，记录完整的执行轨迹、工具调用、结果反馈和得分 2. 反向传播：小批量反射：优化器模型将轨迹按成功/失败分组，按小批量分析共性问题，生成结构化的增/删/改编辑建议 3. 编辑合并与排序：合并重复、矛盾的编辑建议，按预期收益排序，根据当前学习率（编辑预算）截取Top N个编辑 4. 候选技能生成：将选中的编辑应用到当前技能文档，生成候选技能 5. 验证门控：在独立的选择拆分上评估候选技能效果，只有严格优于当前最佳技能时才会被接受，否则被丢弃 6. 负反馈与慢更新：被拒绝的编辑存入拒绝缓冲区作为负反馈；每个周期结束时执行跨周期慢更新，提炼长期稳定的规则写入技能的受保护区域

2.3 核心创新点

  1. 可控文本编辑机制：首次引入文本学习率（编辑预算）概念，限制每轮的编辑数量，避免无控制的重写导致技能漂移，支持常数、线性、余弦等多种学习率调度策略
  2. 验证门控机制：所有编辑必须经过独立验证集的效果验证才能被接受，从机制上避免有害编辑进入最终技能，保证优化过程的稳定性
  3. 拒绝缓冲区：记录所有被拒绝的编辑及其效果下降幅度，作为负反馈指导后续优化，避免重复踩坑
  4. 跨周期慢更新：每个周期结束时对比新旧版本技能的执行差异，提炼长期通用的规则写入技能的受保护区域，避免快速编辑覆盖核心通用知识
  5. 执行环境无关设计：通过轻量适配器适配不同的Agent运行环境（直接对话、Codex、Claude Code等），优化得到的技能可以无缝迁移到不同的执行环境

三、实验效果与验证结果

论文在6个基准测试、7个目标模型、3种执行环境下进行了全面验证，SkillOpt在全部52个测试组合中均取得最优或并列最优效果，碾压所有现有方案。

四、关键技术细节与消融分析

论文通过大量消融实验验证了各个模块的作用：

4.1 核心组件效果

组件 移除后效果下降（SpreadsheetBench） 作用说明
文本学习率（编辑预算） -2.5 控制每轮编辑数量，避免技能漂移
拒绝缓冲区 -4.6 记录失败编辑，避免重复踩坑
跨周期慢更新 -22.5 保留长期通用规则，是所有组件中影响最大的

4.2 超参数鲁棒性

  • 训练集大小：流程类任务（表格、数学）随着训练数据增加效果持续提升，而事实类任务（SearchQA）在20%训练数据时就接近饱和
  • 批量大小：执行批量和反射小批量在较大范围内（执行批量8~全周期，反射小批量1~32）效果波动小于2个百分点，说明算法对超参数不敏感
  • 学习率：编辑预算在1~16范围内都能取得不错的效果，默认值4在大部分任务上表现最优

4.3 优化器能力的影响

优化器模型只在训练阶段使用，部署时不需要，因此可以用最强的模型进行离线优化而不增加部署成本： - 用强优化器（GPT-5.5）比用目标模型本身作为优化器的效果提升30%~60% - 即使使用和目标模型相同的弱优化器，也能恢复56%~74%的最优效果，说明优化流程本身的价值远大于优化器模型的能力

五、迁移能力与落地价值

5.1 多维度迁移能力

SkillOpt生成的技能具有极强的迁移能力，无需重新优化即可跨模型、跨环境、跨任务使用： 1. 跨模型迁移：在GPT-5.4上训练的表格处理技能，迁移到GPT-5.4-mini提升9.4，迁移到GPT-5.4-nano提升3.0，全部为正收益 2. 跨执行环境迁移：在Codex上训练的表格处理技能，迁移到Claude Code直接提升59.7个百分点（从22.1→81.8），甚至超过了在Claude Code上直接优化的效果（80.4） 3. 跨任务迁移：在奥林匹克数学竞赛基准上训练的技能，迁移到通用数学基准Omni-MATH仍有1.3~3.7的正收益

5.2 落地成本与收益

SkillOpt的落地成本极低，收益明确： - 技能大小：最终生成的技能文档只有379~1995token（中位数920token），远小于常规系统prompt的长度，可直接阅读、审计、修改 - 编辑次数：效果提升仅需要1~4次成功编辑（中位数2.5次），99%的候选编辑都会被验证门过滤，最终技能非常精简 - 成本结构：训练成本仅在优化阶段支付一次，部署后没有额外开销，技能可以无限复用 - 典型成本：流程类任务（表格、办公QA）每提升1个百分点仅需要0.6M~3.6M token，成本极低

5.3 典型学习到的技能规则

SkillOpt学到的规则都是可解释、符合人类认知的通用流程，而非过拟合的特定样本知识： - SearchQA：从问题表述推断预期答案类型，选择有共同特征证据支持的最短规范实体 - SpreadsheetBench：先检查工作簿结构和公式，写入计算后的静态值而不是依赖Excel自动重算 - OfficeQA：以解析后的页面为主要证据，锁定表格/日期/单位上下文，精确输出要求的舍入值，不加额外标签 - DocVQA：对于表格、表单、图表，先将问题绑定到精确的视觉行/表头/字段，只复制对齐的答案片段 - LiveMathematicianBench：在最强陈述选择题中，按定理强度排序选项，优先选择有理由的强结果选项而非正确但弱的推论 - ALFWorld：维护感知范围内的已访问/待访问列表，重复同类失败后 diversified 搜索，拿到目标前不要返回目的地

六、局限性与未来方向

6.1 当前局限性

  1. 依赖可量化反馈：优化过程需要自动评分的执行轨迹，对于主观评价的开放域任务，需要更强的人类或模型评估能力
  2. 训练成本：虽然部署后无额外开销，但训练阶段需要执行批量任务和调用优化器模型，对于一次性任务成本较高
  3. 单技能限制：当前只优化单一技能，对于需要多个独立流程的复杂领域，单一技能可能不够
  4. 分布漂移风险：技能是在特定训练分布上学到的启发式规则，迁移到差异极大的场景时需要重新验证

6.2 未来方向

  • 支持跨领域共享的技能库，实现基础设施复用
  • 跨基准复用优化器端的元技能，进一步降低训练成本
  • 支持无奖励或偏好驱动的验证门，适配开放域任务
  • 探索将优化后的技能蒸馏回模型权重的路径，实现技能到知识的转换

七、总结与实践建议

7.1 核心结论

SkillOpt首次实现了Agent技能的可控、稳定、可复现的文本空间优化，无需修改模型权重即可实现17~25个百分点的平均效果提升，生成的技能可解释、可审计、可跨场景迁移，是当前闭源模型领域适配的最优方案。

7.2 落地实践建议

  1. 适用场景优先选择：优先在流程明确、有自动评分机制的场景使用（如数据处理、办公自动化、工具调用、数学推理等），这类场景收益最高
  2. 优化策略：训练阶段用最强的大模型作为优化器，部署时不需要优化器，不增加部署成本
  3. 技能复用：优化得到的技能可以在同领域的不同模型、不同执行环境中直接复用，大幅降低适配成本
  4. 超参数配置：默认使用余弦学习率调度，编辑预算4，执行批量40，反射小批量8，在大部分场景下都能取得不错的效果
  5. 技能审计：最终生成的技能只有不到2000token，上线前可以人工审核，避免学习到有害或不符合业务规范的规则
