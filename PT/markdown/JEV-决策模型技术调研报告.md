## 一、背景

导读：Agent 落地一年多，系统里大量节点需要的不是"一段回答"，而只是一个"判断"。Jev 把这类判断从生成式大模型中单独拆出，做成一种新的模型形态。

### 1.1 问题定义

现代软件（尤其 Agent）的运行循环里充满高频、原子化、接收者本来就是程序的决策点：

- 这条用户请求该路由给哪个部门 / 哪个模型？
- 检索结果与问题是否相关？
- 页面上几十个元素，该点哪一个？
- 这次工具调用是否危险？该自动执行、二次校验还是转人工？
- 循环是否应该终止？失败后要不要重试？

TypeSafe 的判断是：未来大规模 AI 自动化中 **99% 的交互发生在机器之间，只有 1% 面向人**。让一个自回归大模型为每个碎判断"想几秒、写一段、再被解析"，是系统性浪费。

### 1.2 现有两条路线的缺陷

| 路线 | 代表 | 做这类判断时的缺陷 |
|---|---|---|
| 传统判别模型 | BERT / DeBERTa + 分类头 | 标签体系编译期固定，增删一个类别就要重新标注、重新训练；常识储备弱、上下文短；一个任务一个模型 |
| 生成式大模型 | GPT / Claude / Gemini / DeepSeek / 千问 | 选择题也要逐 token 自回归生成，延迟 2–20 秒、双向计费；输出需解析/正则/重试兜底；随口报的"95% 确定"是生成的字符，与真实正确率没有统计关系（伪概率） |

LLM 伪概率的两个具体病理（知乎专栏分析）：

1. **打分虚高**："0.85"只是因为 RLHF 标注员偏好高分和整十数，不代表 85% 的真实发生率；
2. **分布漂移**：prompt 微调一个标点，整批打分分布就可能抬升或下降，下游不敢直接写 `if score > 0.8`。

### 1.3 Jev 的定位

Jev 由前 OpenAI 研究员、InstructGPT/RLHF/ChatGPT 关键贡献者 **Diogo Almeida** 创办的 **TypeSafe AI** 发布（2024 年初离开 OpenAI，4000 万美元融资，闭门研发约两年，2026-09-15 发布，当前为小范围内测）。

官方一句话定义：

```
unstructured state in, typed probabilistic decisions out
（非结构化状态输入 → 带校准概率的强类型决策输出）
```

**直觉类比**：如果大模型是"能写会算的顾问"，Jev 就是物流分拣线上的**自动分流器**——不聊天、不解释，在几十到几百毫秒内把上游来件拨到正确的下游分支。它也像软件里一条"**智能 if 语句**"。

认知科学借喻来自卡尼曼《思考，快与慢》：Jev 是快速直觉的 **System 1**，前沿大模型继续做慢速推演的 **System 2**。模型名 Jev 则取自经济学家杰文斯（W. S. Jevons）与**杰文斯悖论**——资源利用效率越高，总消耗反而越大；商业隐喻是：单次决策成本降到近零，会把"问一下模型"嵌进软件的一切环节。

> 注意能力范围：System 1 的任务集只是 System 2 的一小部分。大模型能做 Jev 的判断题，反过来不成立——Jev 不能写文章、写代码或聊天。

## 二、原理详解

导读：Jev 的技术三件套为「新模型架构 + 并行采样器 + RLCD」。官方未公开网络细节，本章的形式化描述综合官方契约与社区复现资料（NanoJev/CUA-S1），凡属推断均已标注。

### 2.1 形式化定义

给定非结构化状态 `state` 与一组现场声明的决策任务 `tasks`，模型一次返回每个任务的概率分布：

```
输入:  state s ∈ 文本/程序状态
       tasks τ = {τ_1, ..., τ_k}，每个任务含问题与候选集
输出:  对每个 τ_j：候选上的概率分布 P(c | s, τ_j)
       （Score 任务再给期望，Boolean 给 P(true)）
```

三种决策原语：

1. **Choice（多选一）**：候选数 ≤ **255**，对全部候选并行打分、归一化；
2. **Boolean（是/否）**：社区复现资料显示其等价于两个标量差过 sigmoid；
3. **Score（有序评分）**：2–10 个有序档位，返回档位概率与概率加权期望。

Boolean 的标量形式（来自 NanoJev 技术转述，非官方文档）：

```
P(true) = sigmoid(z_true − z_false)
        = 1 / (1 + exp(−(z_true − z_false)))
```

Score 的期望值（客户端计算）：

```
E = Σ_i  P(level_i) · value(level_i)
```

**关键澄清：Jev 不能直接输出自由数值（不能"做回归"）。** 知乎实测：问"明天多少度"，必须给出 25/30/35 等档位让模型分配概率，再由客户端加权平均。三种原语本质上都是分类。

### 2.2 机制解释：为什么快

1. **去掉自回归循环**：state 与全部候选编码后，通过共享骨干网络**一次前向传播**直接算出所有候选的概率张量，输出层没有文本生成通道；
2. **多任务并行**：一封邮件同时问"分类/紧急度/是否退款"，各子问题在同一查询内并行回答；
3. **受限概率空间**：在候选构成的概率单纯形上取值，配合硬件感知并行采样（官方称"对硬件友好"），从机制上消除 JSON 损坏与解析重试；
4. **高基数两阶段**：候选超过 255 时（如上千维基词条），先用 Score 全量粗筛，再用 Choice 对前几十个精选——维基百科 Wikiracing 据此几百毫秒完成一次跳转决策。

### 2.3 RLCD：校准概率从哪来

**RLCD** = Reinforcement Learning for Calibrated Decisions（面向校准决策的强化学习），明确走 RLHF 的反方向：RLHF 优化"人更喜欢的回答"，RLCD 优化"概率对照真实结果是否准确"。

校准目标的直觉形式：

```
校准要求：在模型给出置信度 p 的所有判断中，真实正确率 ≈ p
例：模型长期说 0.8 的那批判断，约 80% 为真
```

官方文档的自我限定（知乎原文转译）："校准在**成组**的预测上度量，**不保证单次回答正确**。"

校准若成立，工程上解锁三种模式：

- **置信度阈值路由**：>0.9 自动放行，0.7–0.9 二次校验，<0.7 转人工；
- **多模型级联**：小模型拿不准再喂大模型，成本压到极致；
- **风险场景自动化**：审核/风控/医疗辅助等"错了要负责"的环节第一次有了可用的概率接口。

### 2.4 "零幻觉"的准确读法

```
结构保证（成立）：候选枚举由调用方锁死，模型不可能输出 schema 之外的内容
事实保证（不成立）：选项之内的判断照样会错
```

Hacker News 高赞评论的反驳：给大模型加上同样的约束解码，大模型一样"不会幻觉"、一样会选错。社区共识一句话：**类型安全 ≠ 事实正确（type-safe ≠ truth-safe）**。

## 三、方案设计

导读：本章给出三种范式的并排对比、目前可查的全部关键实验数据（均带来源与可信度标注），以及 jev-like 方法的演进谱系。

### 3.1 三种范式变体对比

| 维度 | 传统判别模型（BERT/DeBERTa） | 生成式 LLM | System One（Jev） |
|---|---|---|---|
| 核心机制 | Encoder + 静态线性头 | Decoder 自回归逐 token 生成 | 稠密表征 + 单前向并行出全部候选概率 |
| 规则注入 | 标注数据微调，写进权重 | Prompt 自然语言描述 | 请求 Schema 内联 instructions，零样本 |
| 标签灵活性 | 编译期固定，改标签需重训 | 动态，但生成易失控 | 运行时动态指定（≤255），输出天然合法 |
| 常识储备 | 弱 | 极丰富 | 较丰富，继承预训练底座 |
| 上下文 | 短（常 512 token） | 极长 | 中长，依赖底座 |
| 延迟 | 本地 3–15ms | 云端 2–20s | 云端 70–500ms（国内含网络约 300–1200ms） |
| 输出风险 | 无 | JSON 损坏/多余文本/重试 | 无语法层风险，判断仍会错 |
| 概率可信度 | 任务封闭时可校准 | 打分虚高、prompt 敏感 | RLCD 专门校准（独立验证不足） |
| 成本 | 极低（自托管） | 输入输出双向计费，最贵 | $0.042/1M 输入，输出免费 |
| 可解释性 | 可做特征分析 | 能给理由（未必忠实） | 无理由无过程 |

### 3.3 方法演进谱系

```
2018 前后  BERT/DeBERTa 判别器
           Encoder + 固定分类头，一个任务一个模型
              │  问题：标签固定、需标注重训
              ▼
2022+      LLM-as-judge
           大模型零样本做判断/打分，prompt 定义规则

```

## 四、核心实现

导读：本章给出 jev-like 决策调用的最小参考实现（Python 风格伪代码），以及"客户端期望值回归"和"阈值级联"两个关键工程片段。

### 4.1 决策调用

```python
# 伪代码：Jev 风格的结构化决策调用
def decide(state):
    # tasks 在运行时现场声明，无需微调、无需固定标签表
    # 一次请求，服务端并行回答全部子问题
    response = client.decide(
        state=state,
        tasks={
            "category": {
                "type": "choice",
                "question": "这个问题属于哪一类？",
                "options": {
                    "billing":   "账单、扣款、支付问题",
                    "technical": "功能异常、技术故障",
                    "account":   "账号、登录、账户设置",
                },
            },
            "refund_requested": {
                "type": "boolean",
                "question": "用户是否明确要求退款？",
            },
            "urgency": {
                "type": "score",
                "question": "紧急程度？",
                "levels": ["可以等待", "今天处理", "立即处理"],
            },
        },
    )
    # 返回全部为强类型概率，程序可直接消费，无需解析文本
    return response
    # 例：
    # category.probs = {"billing": 0.84, "technical": 0.11, "account": 0.05}
    # refund_requested.p_true = 0.93
    # urgency.expect = 2.7
```

### 4.2 客户端期望值（伪回归）

```python
# Score 档位概率 → 数值期望；这是 Jev 支持"回归"的真实方式
def expected_value(level_probs, level_values):
    # level_probs: {"25": 0.2, "30": 0.5, "35": 0.3}
    # level_values: {"25": 25, "30": 30, "35": 35}
    return sum(level_probs[k] * level_values[k] for k in level_probs)

# expected_value(...) = 25*0.2 + 30*0.5 + 35*0.3 = 30.5
```

### 4.3 阈值级联（价值落地的关键）

```python
# 伪代码：置信度决定自动执行 / 二次校验 / 转人工
def route_with_policy(decision):
    p = decision.confidence          # 模型只负责判断与不确定性
    if p >= 0.9:                     # 政策阈值写死在代码里，不交给模型
        return execute()
    if p >= 0.7:
        return second_check()        # 如换旗舰模型复核
    return hand_off_to_human()
```

工程原则（社区高度认同）：**AI 不应该拥有政策**——模型负责感知、判断、估不确定性；何时执行/降级/交人，由确定性代码决定。

## 五、Jev-like 模型训练流程（复现指南）

导读：官方 Jev 无法训练（闭源 API、结构/参数量/数据未披露、RLCD 无论文无代码）。本章给出复现一个「jev-like 决策模型」的完整流程：数据 → 模型改造 → SFT → 校准强化 → 评估。其中 RLCD 阶段的奖励设计基于官方一句话描述与校准学习常规做法的**合理推断**，标注为推断而非官方配方。

### 5.1 先选路线：由轻到重

| 路线 | 代表 | 是否训练 | 能拿到什么 | 缺什么 |
|---|---|---|---|---|
| 0 · logit 直读 | OpenJev-SGLang | 不训练 | 现成 Qwen 单 token 标签（A/B/C）logit 归一化 + KV 缓存复用 | 无校准，概率需自行验证 |
| 1 · 推理外壳 | Qwen-2.5-1B-RLCD（2 小时复刻） | 不改模型 | 并行约束解码，M4 Max 实测延迟降 5.6–7 倍，输出 100% 合法 | 同 0，仅工程改造 |
| 2 · 轻量微调 | Kev（Qwen2.5-0.5B + LoRA + readout head，M5 上 1 小时 45 分训完） | LoRA + 打分头 | 动态候选项、可用概率，TypeSafe API 兼容 | CE 训练不保证校准 |
| 3 · 窄任务从零训 | CUA-S1-FORMS（70 万参数，6 epoch × 1 万合成 episode） | 全参数 | 2.8MB、单卡毫秒级 | 只做窄任务，不含校准 |

多数业务走到路线 2 即可；想要可写入 `if p > t` 的可信概率，必须再做 5.5 的校准阶段。

### 5.2 阶段一：构造决策数据集（真正的门槛）

每条样本为四元组：

```
(state, question, options, correct_idx)
```

标签两条来源（NanoJev 实证方案）：

1. **程序真值**：规则引擎 / 模拟器直接算出精确标签（"北边有墙 → 不可通行"），零标注成本；
2. **教师软标签**：用相同输入调强模型（或 Jev API）取软概率分布，作为辅助监督信号。

必须刻意构造的三类样本：

- **硬负例**：似是而非的边界选项（如阈值判断里的 1.99 vs 2.00）；
- **无信号样本**：state 中不含答案信息，正确输出应为"无法判断"而非随机硬选；
- **显式拒答标签**：选项集内置 `other / none of the above / skip`。

防泄漏切分：按**任务模板 / 规则族 / 场景分组**切分，训练集与测试集不得共享模板、规则脚本或生成器种子；NanoJev 直接用不同地图做测试集。社区共识：复现的真实门槛不在算力，而在数据合成、硬负例设计与评测集切分。

### 5.3 阶段二：模型改造（LoRA + 动态打分头）

关键点：选项每次请求可变，因此不能把标签写死在输出层，要让**候选项文字也进入模型**，由打分头比较「问题表示」与「各候选表示」：

```python
# 底座：Qwen2.5-0.5B/1B（或任意本地小模型），主体冻结 + LoRA 适配器
# 训练部件：LoRA + 小型 readout 打分头

def readout_head(q_hidden, opt_hiddens, temperature=1.0):
    # q_hidden: [d] 问题表示；opt_hiddens: [K, d] K 个候选各自的表示
    logits = (opt_hiddens @ q_hidden) / (sqrt(d) * temperature)
    return softmax(logits, axis=0)        # K 可在运行时动态变化（≤255）

# Boolean = K=2；Score = 有序档位走同一头，期望值客户端加权
p_true = sigmoid(z_true - z_false)
```

多问题 packed 训练（Kev 做法）：同一 state 的多个子问题 pack 进同一批计算，用注意力掩码规定每个问题只能看见公共材料与自己的选项、看不见其他问题，等价于一次前向并行答完所有字段。

### 5.4 阶段三：SFT（训完即可用）

```python
# 硬标签：对正确选项做交叉熵 —— 天然重罚"自信地答错"
loss_hard = cross_entropy(logits, correct_idx)

# 可选：教师软标签对齐（蒸馏概率形状）
loss_soft = KL(teacher_probs || model_probs)

loss = loss_hard + 0.5 * loss_soft
```

注意：交叉熵只惩罚自信答错，**不直接保证分组频率校准**——这是 SFT 与 RLCD 的分界线。

### 5.5 阶段四：RLCD 校准（核心壁垒，推断配方）

目标：模型说 0.8 的那批样本，长期约 80% 为真。由低成本到强化学习两级：

**方案 A · 后校准（先试，半天见效）**：冻结模型，在独立校准集上做 temperature scaling（只学一个温度 T）或 isotonic regression：

```
校准后概率 = softmax(logits / T)      # T>1 抹平过度自信
```

**方案 B · 校准强化（RLCD 的对应物，推断）**：决策是单步 bandit、没有多步轨迹，不需要完整 PPO，可用 GRPO 式离策略更新：

```python
# 奖励采用适当评分规则（proper scoring rule）
reward_brier   = -(p_correct - 1) ** 2     # 负 Brier 分数
reward_log     = log(p_correct)            # 对数评分
# 无信号样本：奖励高熵/拒答，惩罚硬选
reward_unknown = entropy(p) - miss(skip)
# 额外 ECE 分桶惩罚：按置信度分桶，桶内真实频率偏离置信度即扣分
reward_ece     = -ECE_buckets(p, y)
```

训练时加 KL 约束防止偏离 SFT 策略。官方 RLCD 未公开细节，以上为校准学习标准做法的工程化推断。

### 5.6 评估四件套

1. **准确率 / Macro-F1**（类别不均衡时）；
2. **校准指标**：可靠性曲线（reliability diagram）、ECE、Brier score，分桶核对；
3. **泛化切片**：OOD 规则族、硬负例、无信号对照组——无信号时应输出"无法判断"而非掉到随机；
4. **拒答质量**：`skip/other` 的召回率与误拒率。

目前所有开源复现（Kev / NanoJev / CUA-S1）都只报告了准确率，**没有一家拿出校准曲线**——校准是 RLCD 宣称的壁垒中唯一尚未被独立复现的部分。

## 六、结论与选型建议

导读：Jev 更像"被验证了的产品方向与接口范式"，而不是已被充分证明的精度答案。

### 6.1 编号结论

1. **速度/成本优势真实可感**：非自回归单前向决策 70–500ms、$0.042/1M 输入、输出免费，在高频结构化判断上量级成立；
2. **裸模型精度中等**：中文客服实测 64%–65.2%、自有样本 Macro-F1 约 70%，均不优于同场便宜模型，旗舰模型明显更准；
3. **"零幻觉"是结构保证**：类型安全 ≠ 事实正确，选项之内照样选错；
4. **校准是核心卖点也是最大未知数**：RLCD 的独立验证、长尾/OOD 校准均无公开证据；无信号任务会掉回随机水平；
5. **真实价值在级联端到端**：决策小模型 + 生成大模型 + 确定性代码的三层分工，配合兜底才能同时拿到准确率与成本；
6. **生态信号强**：Vercel 13%/24h 的采用速度、LangChain 次日集成、开源 0.5B–1.5B（乃至 70 万参数）复现，证明需求真实存在；
7. **开源复刻不等于 Jev**：社区项目普遍只复刻结构化输出，不承诺概率校准；真实门槛在数据合成、硬负例与评测切分。

### 6.2 工程上线 checklist

- ☐ 用**真实业务分布**自建评测集，而非供应商示例
- ☐ 同时报告"全对率"与"单字段准确率/Macro-F1"两个口径
- ☐ 包含硬负例/边界样本切片（如 1.99 vs 2.00）
- ☐ 包含**无信号/空差异对照组**，检验是否在没信息时硬选
- ☐ 校准评估：可靠性曲线、ECE、Brier score，分置信度桶核对
- ☐ 效率评估：P50/P95 延迟（含网络）、每千题成本、吞吐
- ☐ 级联评估：兜底后的整体准确率、兜底比例、总成本
- ☐ prompt 稳定性：同义改写下概率分布的漂移幅度
- ☐ Choice 选项内置 `other / none of the above`（或 skip）显式拒答出口
- ☐ 策略阈值、权限、人工兜底全部留在确定性代码中
- ☐ 灰度上线：高分自动、中分复核、低分人工，先用于可逆低风险节点
- ☐ 上线后持续监控分桶准确率与分布漂移
