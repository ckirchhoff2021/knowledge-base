一、背景与训练目标

客服分流、风控拦截、审批路由、A/B 实验判读等场景，本质是高频、结构化、可枚举选项的单步判断。通用大模型逐次生成自然语言答案存在解析失败、延迟高、成本高三个问题。Jev 范式让小模型直接输出"选项 + 概率"：输出约束在候选集内（类型安全，解析成功率 100%）、单前向决策低成本、概率可写入确定性代码做阈值级联。

1.2 为什么选 Qwen3.5-4B

维度匹配点
能力足够4B 结构化理解与中文能力明显强于 0.5B/1B
资源可承受bf16 LoRA 约 10GB 显存；Q4_K_M 约 2.74GB，可边缘部署
架构先进GDN 线性注意力 + 全注意力混合（约 3:1），吞吐高
生态成熟Unsloth 支持 SFT/GRPO；vLLM/SGLang/Ollama 全链路
多模态原生图文，可消费截图、表单、扫描件

1.3 目标与非目标

目标：在业务评测集达到约定准确率/F1；输出 100% 合法、无信号主动拒答；概率校准后 ECE 达标；产出 16bit、GGUF、在线服务三种形态。非目标：不复刻官方 RLCD；不做开放式生成；本阶段不做多步轨迹强化（决策是单步 bandit）。

1.4 验收指标（建议起步线）

指标目标值说明
全对率≥ 90%级联兜底口径另算
单字段 Macro-F1≥ 0.85类别不均衡时主看
输出合法率100%约束解码保证
无信号 skip 召回≥ 0.95防止没信息硬选
ECE≤ 0.05校准核心 KPI
Brier score≤ 0.15越小越好
P95 延迟≤ 300msvLLM 批服务口径
级联后整体准确率≥ 0.96兜底比例 ≤ 15%
以上准确率为工程目标值而非 Jev 官方数据，须以业务评测集实测为准。

二、总体方案：双路线选型与全流程

2.1 两条技术路线

维度路线 A：单 token 约束解码路线 B：readout 打分头
输出字母 A/B/C 或 S(skip)问题向量 × 候选向量打分
候选项写进 prompt，运行时可变运行时可变（≤255）
结构改动无新增图外打分头
转 GGUF/Ollama顺畅不支持，需自托管
训练标准 SFT(LoRA)LoRA + 打分头联合训练
适用绝大多数业务（主推）候选极多/跨字段共享表示
选型结论
4B 基座下首选路线 A：不改结构、转换部署零障碍；仅当候选集合极大且 prompt 化实测有损失时，对该字段单独启用 B 并坚持 HF/vLLM 自托管。

2.2 全流程六阶段

①数据工程 → ②SFT(LoRA) → ③概率校准 → ④评估门禁 → ⑤格式转换 → ⑥部署级联
   ↑________________________ 难例回流 / 反馈 ________________________|

数据用程序真值 + 教师软标签，造硬负例/无信号/拒答样本；SFT 主体冻结 + LoRA 只对答案 token 计 CE；独立校准集做 temperature scaling；评估四件套达标才转换；合并 16bit 与 Q4_K_M GGUF；上线做阈值级联，难例回流再训。

三、基座模型：Qwen3.5-4B 特性与适配

项目说明
型号Qwen/Qwen3.5-4B（2026 开源小模型系列 0.8B/2B/4B/9B 之一）
架构Gated DeltaNet(GDN) 线性注意力 + 标准全注意力，约 3:1 混合
多模态原生图文（亦有纯文本 Base 版）
体积BF16 约 8.4GB；Q4_K_M 约 2.74GB；Int4 推理约 3GB 显存

3.2 混合架构对训练的三点影响（勿照搬 Qwen2.5）

  1. LoRA 挂载点先打印确认：训练前列出 model.named_modules()，核对注意力投影与 MLP 是否齐全，GDN 线性注意力投影命名可能不同，按实际名挂载；
  2. GDN 有状态/门控：线性注意力带循环状态，packed 训练掩码必须正确，避免跨样本状态串扰；
  3. MTP 不在决策阶段启用：多 token 预测会改变答案分布，训练/导出保持单 token 答案。

3.3 关闭 thinking

在 chat template/配置设置 enable_thinking=False，上线再用解码 logit 约束只放行答案字符集双保险；喂样本验证输出只有一个合法字符后再批量训练。

四、数据工程方案

每条样本为四元组，标签以程序真值为主（规则引擎/模拟器精确打标），教师强模型软标签为辅：

sample = {
  "task_id": "risk_rule_family_07",          # 规则族，用于分组切分
  "state": "订单金额:199.99; 用户风险分:62",   # 材料（可含图片）
  "question": "是否需要人工复核该订单？",
  "options": ["自动放行","拦截","转人工"],       # 运行时可变
  "correct_idx": 2,                           # -1 = 无信息→skip
  "teacher_probs": [0.1, 0.2, 0.7]            # 可选软标签
}
必造样本构造目的
硬负例（约 25%）199.99 vs 200.00、同义改写、缺字段、否定语序学真实判据而非表面词
无信号（约 15%）删除解题所需字段，标签=skip没信息时拒答
显式拒答选项内置 other/none/skip合法逃生出口
数据集建议规模用途
训练集5万～10万 episodeLoRA SFT
校准集5千～1万（不重叠）temperature/isotonic
验证集3千～5千选模、早停
测试集5千～1万（含 OOD 规则族）最终门禁

防泄漏：按规则族/模板/生成器种子分组切分，训练测试不共享规则脚本，保留整组未见规则族；先用 1 万条冒烟跑通再放大。

五、模型改造方案

5.1 路线 A：LoRA + 单 token（主推）

from unsloth import FastLanguageModel
model, tok = FastLanguageModel.from_pretrained(
    model_name="Qwen/Qwen3.5-4B", max_seq_length=4096, load_in_4bit=False)
# target_modules 必须以 model.named_modules() 实际结果为准（GDN 混合架构）
model = FastLanguageModel.get_peft_model(
    model, r=32, lora_alpha=32, lora_dropout=0.0,
    target_modules=["q_proj","k_proj","v_proj","o_proj",
                    "gate_proj","up_proj","down_proj"])

def to_messages(ex):
    opts = "\n".join(f"{chr(65+i)}. {o}" for i,o in enumerate(ex["options"]))
    ans = chr(65+ex["correct_idx"]) if ex["correct_idx"] >= 0 else "S"
    return {"messages": [
        {"role":"system","content":"只输出单个字母；信息不足输出 S。不要解释。"},
        {"role":"user","content":f"{ex['state']}\n问题:{ex['question']}\n{opts}"},
        {"role":"assistant","content":ans}]}

只对 assistant 答案 token 计 loss（completion-only mask）；多子问题用 attention 掩码隔离。

5.2 路线 B：readout 打分头（可选，自托管）

def readout_logits(q_hidden, opt_hiddens):
    d = q_hidden.shape[-1]
    return (opt_hiddens @ q_hidden) / (d ** 0.5)   # softmax 即概率，K 可变
# Boolean(K=2)：p = sigmoid(z_true - z_false)

该头是图外模块，GGUF/llama.cpp 不支持，只能 HF/vLLM 自托管并注册结构。

5.3 LoRA 超参（建议起步）

超参建议值说明
r / alpha32 / 324B 上 16～64 之间
lora_dropout0.0数据小取 0.05
target_modules注意力 + MLP 全投影以实际模块名为准
max_seq_length4096按 state 长度调

六、训练方案：SFT → 校准 → 可选强化

6.1 SFT

loss_hard = CrossEntropy(logits, correct_idx)        # 重罚自信答错
loss_soft = KL(teacher_probs || model_probs)         # 可选蒸馏
loss = loss_hard + 0.5 * loss_soft
项目建议值
epochs2～3（先 1 轮看曲线）
有效 batch32～64（梯度累积）
学习率1e-4（5e-5～2e-4）
schedulecosine，warmup 3%，bf16

监控训练/验证 loss、答案合法率、无信号切片 skip 比例与混淆矩阵；完成后冻结 sft-v1 再校准。

6.2 概率校准（独立数据）

# 方案 A：temperature scaling（先做，半天见效）
校准后概率 = softmax(logits / T)      # T>1 抹平过度自信，仅学标量 T
# 方案 B：isotonic regression（A 不够时，注意过拟合）

校准集与训练/测试严格不重叠；校准后 ECE、Brier 显著改善且测试不反弹才算通过。

6.3 可选：单步校准强化（GRPO）

A_i = (r_i - mean(r)) / (std(r) + eps)             # 组采样，无需 Critic
reward_brier   = -(p_correct - 1)**2                # 负 Brier
reward_log     = log(p_correct)                     # 对数评分
reward_unknown = entropy(p) - miss(skip)            # 无信息鼓励高熵/拒答
reward_ece     = -ECE_buckets(p, y)                 # 分桶惩罚 + KL 约束

单步任务后校准通常已足够，强化列为可选项。

6.4 训练计划

迭代数据出口
第 0 轮冒烟5千～1万跑通链路、核对 GDN 模块名与掩码
第 1 轮5万～10万SFT + 校准，达门禁即灰度
第 2 轮+ 线上难例难例回流再训，必要时 GRPO

七、评估方案与验收标准

四件套：准确性（全对率 + Macro-F1）、校准（可靠性曲线/ECE/Brier）、泛化切片（OOD/硬负例/无信号）、拒答质量（skip 召回与误拒）。

维度指标门禁
准确单字段 Macro-F1 / 全对率≥ 0.85 / ≥ 0.90
合法输出合法率= 1.00
校准ECE / Brier≤ 0.05 / ≤ 0.15
拒答skip 召回 / 误拒率≥ 0.95 / ≤ 0.05
泛化OOD F1 较同分布下降≤ 5 个百分点
效率P95 延迟≤ 300ms

系统级：加兜底后整体准确率 ≥0.96、兜底比例 ≤15%、每千题成本、P50/P95 延迟、prompt 同义改写稳定性。任一不达标回第 6 章定位，不放行。

八、格式转换与部署方案

# ① 合并 LoRA → 16bit safetensors（vLLM/SGLang）
model.save_pretrained_merged("jev-qwen35-4b", save_method="merged_16bit")
# ② 仅 LoRA 适配器（便于 A/B 与回滚）
model.save_pretrained("jev-qwen35-4b-lora")
# ③ GGUF（Ollama/llama.cpp）
model.save_pretrained_gguf("jev-qwen35-4b-gguf", quantization_method="q4_k_m")

约束解码：vLLM 用 guided/structured outputs 的 choices=["A","B","C","S"]；SGLang 用 choices/约束生成并复用 KV 缓存做多字段并行；Ollama/llama.cpp 用 grammar(GBNF) 或 logit bias 限制答案字符集。prompt 与解码层双约束，合法率必须 100%。

python -m vllm.entrypoints.openai.api_server --model ./jev-qwen35-4b --port 8000
# 请求侧对答案字段传 guided_choice=["A","B","C","S"]

def decide(p, field):
    if field.skippable and p.argmax() == SKIP: return route("human","no_signal")
    if p.max() >= 0.90: return auto_execute()     # 高置信自动
    if p.max() >= 0.60: return verify_with_llm()   # 中置信复核
    return route("human")                          # 低置信人工

十一、结论与工程 Checklist

  1. Qwen3.5-4B + LoRA 单 token 约束解码是性价比最高的 Jev-like 路线，不改结构、转换零障碍；
  2. 真正门槛是数据：硬负例、无信号、按规则族切分比调参更决定成败；
  3. 校准是独立阶段：SFT 不保证概率可用，temperature scaling 先做、ECE/Brier 门禁；
  4. GDN 混合架构需专门核对：LoRA 挂载点与 packed 掩码不能照搬 Qwen2.5；
  5. 价值在级联而非单点：判别器 + 大模型 + 确定性代码 + 人工兜底；
  6. 强化非必需：单步任务后校准通常足够，GRPO 按需启用。
上线前 Checklist
  • ☐ 真实业务分布评测集；同时报告全对率与单字段 Macro-F1
  • ☐ 含硬负例/边界样本、无信号对照组；测 skip 召回/误拒
  • ☐ 校准：可靠性曲线、ECE、Brier 分桶核对
  • ☐ 选项内置 other/skip；关 thinking；解码约束到合法字符集（100% 合法）
  • ☐ LoRA target_modules 已按 GDN 实际模块名核对；三种产物转换验证
  • ☐ P50/P95 延迟、每千题成本、兜底比例压测
  • ☐ 阈值/权限/兜底留在确定性代码；先灰度低风险节点；监控与难例回流就绪
