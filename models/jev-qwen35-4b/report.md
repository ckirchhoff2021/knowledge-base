## 一、背景与训练目标

### 1.1 问题定义

客服分流、风控拦截、审批路由、A/B 实验判读等场景，本质是**高频、结构化、可枚举选项的单步判断**。用通用大模型逐次生成自然语言答案，存在三个问题：输出不保证合法（解析失败）、延迟高（700ms 以上）、成本高。

Jev 范式用一个小模型直接输出"选项 + 概率"：

- 输出被约束在候选集合内（类型安全），**解析成功率 100%**；
- 单前向决策，延迟与成本低一个量级；
- 概率可写入确定性代码做阈值级联（自动/复核/转人工）。

### 1.2 为什么选 Qwen3.5-4B

| 选择维度 | Qwen3.5-4B 的匹配点 |
|----------|---------------------|
| 能力足够 | 4B 在结构化理解、指令遵循上明显强于 0.5B/1B，中文场景稳 |
| 资源可承受 | bf16 LoRA 约需 10GB 显存；Q4_K_M 量化约 2.74GB，可边缘部署 |
| 架构先进 | GDN 线性注意力 + 全注意力混合（3:1），吞吐高、长文友好 |
| 生态成熟 | Unsloth 已支持 SFT 与 GRPO；vLLM/SGLang/Ollama 全链路可部署 |
| 多模态 | 原生图文，可直接消费截图、表单、扫描件等视觉输入 |

### 1.3 训练目标与非目标

**目标（本方案交付物）：**

1. 训练一个以 Qwen3.5-4B 为底座的决策模型，在业务评测集上达到约定准确率与 Macro-F1；
2. 输出 100% 合法（落在选项集或 `skip`），无信号时主动拒答而非随机硬选；
3. 概率经过校准，ECE 控制在可接受范围；
4. 产出可部署的三种形态：合并 16bit（vLLM/SGLang）、GGUF（Ollama/llama.cpp）、在线服务约束解码。

**非目标：**

- 不追求复现官方 RLCD 的内部实现（无公开资料），用标准校准方法达到校准目标即可；
- 不做开放式生成，模型只做判别；复杂解释交给级联的大模型；
- 不在本阶段做多智能体与多步轨迹强化（决策是单步 bandit）。

### 1.4 验收指标（目标值，立项时与业务方确认）

| 指标 | 目标值（建议起步线） | 说明 |
|------|----------------------|------|
| 全对率（整单全字段对） | ≥ 90% | 级联兜底口径另算 |
| 单字段 Macro-F1 | ≥ 0.85 | 类别不均衡时主看 |
| 输出合法率 | 100% | 由约束解码保证 |
| 无信号样本 skip 召回 | ≥ 0.95 | 防止"没信息硬选" |
| ECE（期望校准误差） | ≤ 0.05 | 校准阶段核心 KPI |
| Brier score | ≤ 0.15 | 越小越好 |
| P95 延迟（含网络） | ≤ 300ms | vLLM 批服务口径 |
| 级联后整体准确率 | ≥ 0.96 | 兜底比例 ≤ 15% |

> 以上准确率目标为**工程目标值而非 Jev 官方数据**；真实可达水平必须用业务评测集实测，不可写成 Jev 承诺。

## 二、总体方案：双路线选型与全流程

### 2.1 两条技术路线

Jev-like 的核心是"如何把候选项变成模型输出"。有两条路线，**本方案主推路线 A**：

| 维度 | 路线 A：单 token 约束解码 | 路线 B：自定义 readout 打分头 |
|------|---------------------------|-------------------------------|
| 输出形态 | 输出字母 `A/B/C/...` 或 `S`(skip) | 问题向量 × 各候选向量打分 softmax |
| 候选项数量 | 写进 prompt，运行时可变 | 运行时可变（≤255） |
| 模型结构改动 | 无（纯提示 + 解码约束） | 新增图外打分头，需注册新结构 |
| 转 GGUF/Ollama | ✅ 完全顺畅 | ❌ 自定义头无法进 GGUF |
| 训练方式 | 标准 SFT（LoRA） | LoRA + 打分头联合训练 |
| 概率来源 | 候选首 token 的 logits | 打分头 logits |
| 适用 | 绝大多数业务（4B 精度足够） | 候选极多/需跨字段共享表示 |

**选型结论**：4B 基座下首选路线 A——不改网络结构，转换部署链路零障碍；只有当候选集合极大（如几十个）、且实测 prompt 化损失明显时，才为相应字段单独启用路线 B 并坚持 HF/vLLM 自托管。下文以路线 A 为主线，路线 B 差异点在第 5 章标注。

### 2.2 全流程总览（六阶段）

```
①数据工程  →  ②SFT(LoRA)  →  ③概率校准  →  ④评估门禁  →  ⑤格式转换  →  ⑥部署级联
   ↑________________________________________反馈 / 难例回流___________________|
```

1. **数据工程**：程序真值 + 教师软标签，合成决策数据集，构造硬负例/无信号/拒答样本；
2. **SFT**：Qwen3.5-4B 主体冻结 + LoRA，只对答案 token 计交叉熵；
3. **校准**：独立校准集做 temperature scaling（必要时 isotonic），把概率对齐真实频率；
4. **评估门禁**：准确率/校准/拒答/延迟四件套达标才放行（第 7 章）；
5. **格式转换**：合并 16bit 与导出 Q4_K_M GGUF；
6. **部署级联**：判别器 + 阈值级联，高分自动、中分复核、低分人工；线上难例回流到数据工程。

> 配套架构图：[图 1 · 训练与转换流水线](diagrams/1-training-pipeline.html)

### 2.3 方案的关键设计决策

1. **单 token 答案**：让答案稳定映射到单个 token，约束解码只放行合法字符，从结构上消灭解析失败；
2. **关闭 thinking**：Qwen3.5 默认带思考模式，决策任务必须关闭，否则输出不是单 token、延迟暴涨；
3. **校准与训练解耦**：先用 SFT 拿到准确率，再用独立校准集修概率，互不污染；
4. **门禁制**：任何一项指标不达标不进入转换/上线，避免"准确率够了但概率不可用"；
5. **确定性代码外置**：阈值、权限、兜底逻辑全部留在代码里，模型只输出选项与概率。

## 三、基座模型：Qwen3.5-4B 特性与适配

### 3.1 模型规格（公开资料）

| 项目 | 参数 / 说明 |
|------|-------------|
| 型号 | `Qwen/Qwen3.5-4B`（通义 2026 年开源小模型系列 0.8B/2B/4B/9B 之一） |
| 架构 | 混合架构：Gated DeltaNet（GDN）线性注意力 + 标准 Softmax 全注意力，约 **3:1** 配比 |
| 多模态 | 原生支持图文（Base 版亦提供纯文本） |
| 权重格式 | 官方发布 safetensors（HF 格式） |
| 上下文 | 长上下文能力（系列支持至 1M token） |
| 精度体积 | BF16 约 8.4GB；Q4_K_M GGUF 约 2.74GB；Int4 推理最小约 3GB 显存 |

### 3.2 混合架构对训练的三点影响（必须核对，勿照搬 Qwen2.5）

GDN 层用 Delta Rule 做线性注意力，模块命名与投影结构不同于纯 Transformer：

1. **LoRA 挂载点要先打印确认**：训练前先列出 `model.named_modules()`，核对注意力投影（`q_proj/k_proj/v_proj/o_proj`）与 MLP（`gate/up/down_proj`）是否齐全；GDN 层的线性注意力投影可能命名不同，按实际模块名挂载，不要照抄旧脚本；
2. **GDN 层有状态/门控**：线性注意力带循环状态，做 packed 训练时掩码必须正确，避免跨样本状态串扰；
3. **MTP（多 token 预测）**：Qwen3.5 支持 MTP，可在推理提速；但**决策阶段我们要的是单 token 稳定答案**，训练与导出时不启用 MTP，避免答案分布变化。

### 3.3 关键适配：关闭 thinking 模式

Qwen3.5 默认输出思考链，对"单 token 决策"是灾难。两种关闭方式（按部署形态选）：

- 模板/配置层：按官方说明在 chat template 或配置中设置 `enable_thinking=False`；
- 解码层：上线时用 logit 约束只允许答案字符集（第 8 章），双保险。

验证方法：喂一条样本，确认输出**只有一个合法字符**、无任何思考前缀，再开始批量训练。

### 3.4 本地获取与环境

```bash
python -m venv .venv && source .venv/bin/activate
pip install unsloth vllm sglang            # 训练 + 服务
# 转换另需 llama.cpp（含 llama-quantize / convert 脚本）
# 权重（二选一）
huggingface-cli download Qwen/Qwen3.5-4B
# 或 export VLLM_USE_MODELSCOPE=true 后用 ModelScope 拉取
```

> 无高端 GPU 的同学，可先用 Unsloth 放出的 Qwen3.5-4B GGUF（Q4_K_M）在本地验证推理链路，但**训练仍需支持 LoRA 的 GPU 环境**（4B bf16 LoRA 建议 ≥12GB 显存）。

## 四、数据工程方案

> 复现的真实门槛不在算力，而在数据合成、硬负例设计与评测切分。本章给出可直接落地的数据规格、规模与生产流程。

### 4.1 样本结构（四元组）

每条样本：

```
sample = {
  "task_id":      "risk_rule_family_07",   # 规则族，用于分组切分
  "state":        "订单金额:199.99; 用户风险分:62; 收货地:...",  # 材料（可含图片占位）
  "question":     "是否需要人工复核该订单？",
  "options":      ["自动放行","拦截","转人工"],                  # 运行时可变
  "correct_idx":  2,                                            # -1 表示无信息→skip
  "teacher_probs":[0.1, 0.2, 0.7],                              # 可选，教师软标签
  "hard_negative": true                                         # 标记硬负例
}
```

标签两条来源：

1. **程序真值（主力，零标注成本）**：规则引擎/模拟器直接算出精确标签（"金额≥阈值且风险分≥60 → 转人工"）；
2. **教师软标签（辅助）**：用强模型（或 Jev API）对相同输入取软概率，用于蒸馏概率形状、软化边界。

### 4.2 三类必造样本（决定模型是否"靠谱"）

| 类型 | 构造方式 | 目的 |
|------|----------|------|
| 硬负例 | 边界对抗：阈值 `199.99 vs 200.00`、同义改写、缺失字段、否定语序 | 逼模型学真实判据而非表面词 |
| 无信号样本 | 从 state 中删除解题所需字段，正确标签 = `skip`(-1) | 没信息时拒答，不掉回随机 |
| 显式拒答 | 选项集内置 `other / none / skip`；选项全错时选它 | 提供合法"逃生出口" |

建议比例（起步）：正常样本约 60%、硬负例约 25%、无信号/拒答约 15%，按业务难度再调。

### 4.3 数据规模与生产节奏

| 数据集 | 建议规模 | 用途 |
|--------|----------|------|
| 训练集 | 5 万～10 万 episode（每 episode 可含多字段子问题） | LoRA SFT |
| 校准集 | 5 千～1 万（与训练集同分布、不重叠） | temperature/isotonic |
| 验证集 | 3 千～5 千 | 训练期选模、早停 |
| 测试集 | 5 千～1 万（含 OOD 规则族） | 最终门禁 |

规模为**建议起步值**：先用 1 万条跑通全链路（`--test` 性质），确认曲线正常再放大；4B 对数据质量敏感，宁少勿滥。

### 4.4 防泄漏切分（按规则族分组）

- 按 `task_id` 的**规则族 / 模板 / 生成器种子**分组切分，训练与测试不得共享同一规则脚本或模板；
- 测试集中保留**整组未见的规则族（OOD）**，检验泛化而非记忆；
- 程序真值场景可直接用"不同生成器配置/不同地图"做测试集；
- 切分后统计各集合的选项分布，避免某档位只出现在训练集。

### 4.5 数据生产流水线

```
规则/场景配置 → 生成器批量产 episode → 程序真值打标
                                      ├→ 教师模型补软标签（抽样）
                                      ├→ 硬负例注入器
                                      └→ 去重/清洗/格式校验 → 分组切分入库
线上难例 ───────────────────────────────────────────────────→ 回到生成器
```

清洗规则：去重（state 完全或近重复）、选项非空、`correct_idx` 合法、多模态引用可访问；校验失败的样本丢弃并记录比例。

## 五、模型改造方案

### 5.1 路线 A：LoRA + 单 token 决策（主推）

模型主体冻结，仅训练 LoRA 适配器，答案走单 token。

```python
from unsloth import FastLanguageModel

model, tok = FastLanguageModel.from_pretrained(
    model_name="Qwen/Qwen3.5-4B",
    max_seq_length=4096,
    load_in_4bit=False,          # 有 12GB+ 用 bf16；显存紧可 4bit 训练
)

# ⚠️ target_modules 必须以 model.named_modules() 实际结果为准（GDN 混合架构）
model = FastLanguageModel.get_peft_model(
    model,
    r=32, lora_alpha=32, lora_dropout=0.0,
    target_modules=["q_proj","k_proj","v_proj","o_proj",
                    "gate_proj","up_proj","down_proj"],
)
```

提示词模板（答案恒为单字符）：

```python
def to_messages(ex):
    opts = "\n".join(f"{chr(65+i)}. {o}" for i, o in enumerate(ex["options"]))
    ans = chr(65 + ex["correct_idx"]) if ex["correct_idx"] >= 0 else "S"
    return {"messages": [
        {"role":"system","content":"只输出单个字母；信息不足输出 S。不要解释。"},
        {"role":"user","content":f"{ex['state']}\n问题:{ex['question']}\n{opts}"},
        {"role":"assistant","content":ans},
    ]}
```

要点：只对 assistant 答案 token 计 loss（completion-only mask）；多轮/多子问题用 attention 掩码隔离。

### 5.2 路线 B：readout 打分头（可选，需自托管）

当候选项动态且 prompt 化有损失时，加一个小型打分头，让候选文字也进入模型：

```python
import torch, torch.nn.functional as F

def readout_logits(q_hidden, opt_hiddens):
    # q_hidden:[d] 问题表示；opt_hiddens:[K,d] 各候选表示
    d = q_hidden.shape[-1]
    scores = (opt_hiddens @ q_hidden) / (d ** 0.5)
    return scores                       # softmax 后即概率；K 运行时可变

# Boolean(K=2) 特例：p = sigmoid(z_true - z_false)
```

联合训练：LoRA 输出的表示喂入打分头，与 LoRA 一起反传。**代价**：该头是图外模块，GGUF/llama.cpp 不支持，只能用 HF/vLLM 自托管并注册结构。

> 配套架构图：[图 2 · 双路线决策头设计](diagrams/2-decision-heads.html)

### 5.3 LoRA 超参（建议起步，需小流量确认）

| 超参 | 建议值 | 说明 |
|------|--------|------|
| r（秩） | 32 | 4B 上 16～64 之间；过大易过拟合 |
| lora_alpha | 32 | 常取与 r 相同（缩放 1） |
| lora_dropout | 0.0 | 数据大可取 0；数据小取 0.05 |
| target_modules | 注意力 + MLP 全投影 | 以实际模块名为准 |
| max_seq_length | 4096 | 按 state 长度调，太长浪费显存 |
| 可训练参数占比 | 约 1%～3% | LoRA 远小于全参微调 |

## 六、训练方案：SFT → 校准 → 可选强化

### 6.1 阶段一：SFT（主体）

**损失函数：**

```
# 硬标签：对正确选项做交叉熵（天然重罚"自信地答错"）
loss_hard = CrossEntropy(logits, correct_idx)

# 可选：教师软标签蒸馏概率形状
loss_soft = KL(teacher_probs || model_probs)

loss = loss_hard + 0.5 * loss_soft      # 无教师样本时 loss_soft=0
```

**训练超参（建议起步）：**

| 项目 | 建议值 |
|------|--------|
| epochs | 2～3（先 1 轮试跑看曲线） |
| 有效 batch size | 32～64（用梯度累积凑） |
| 学习率 | 1e-4（LoRA 常用 5e-5～2e-4） |
| lr schedule | cosine，warmup 3% |
| 精度 | bf16（显存紧 4bit 量化训练） |
| 序列打包 | 可开启，但掩码必须隔离样本与 GDN 状态 |
| 早停 | 验证集 Macro-F1 连续若干步不降则停 |

**训练期监控：** 训练/验证 loss 差（过拟合）、答案合法率、无信号切片 skip 比例、各档位混淆矩阵。SFT 完成后先冻结一版 `sft-v1`，再做校准。

### 6.2 阶段二：概率校准（核心，独立数据）

SFT 的交叉熵只惩罚自信答错，**不保证"说 0.8 长期约 80% 为真"**。在**独立校准集**上做：

**方案 A（先做，半天见效）· Temperature Scaling：**

```
校准后概率 = softmax(logits / T)     # T>1 抹平过度自信，仅学一个标量 T
```

在校准集上最小化负对数似然求 T；路线 B 对打分头 logits 同样适用。

**方案 B（A 不够时）· Isotonic Regression：** 非参数单调映射，灵活但更易过拟合，需足够大的校准集。

验收：校准后 ECE、Brier score 显著改善且测试集不反弹；校准集与训练/测试严格不重叠。

### 6.3 阶段三（可选）：单步校准强化

决策是**单步 bandit、无多步轨迹**，不需要完整 PPO。若后校准仍不达标，可用 GRPO 式更新：

```
# 组采样：同一题生成 K 个候选决策，组内标准化优势，无需 Critic
A_i = (r_i - mean(r)) / (std(r) + eps)

# 奖励：适当评分规则（proper scoring rule）
reward_brier   = -(p_correct - 1)^2        # 负 Brier
reward_log     = log(p_correct)            # 对数评分
reward_unknown = entropy(p) - miss(skip)   # 无信号：鼓励高熵/拒答
reward_ece     = -ECE_buckets(p, y)        # 分桶频率偏离置信度即扣分
# 训练时加 KL 约束，防止偏离 SFT 策略
```

Unsloth 已提供 GRPO 训练入口（LoRA + 4bit + vLLM 加速采样），可低显存跑通；但对单步任务，**后校准通常已足够，强化列为可选项而非必做项**。

### 6.4 训练计划（建议两迭代）

| 迭代 | 数据 | 目的 | 出口 |
|------|------|------|------|
| 第 0 轮（冒烟） | 5 千～1 万 | 跑通训练/校准/转换链路，验证明 GDN 模块名与掩码 | 能产出合法输出 |
| 第 1 轮 | 5 万～10 万 | 正式训练 + temperature 校准 | 达门禁即灰度 |
| 第 2 轮（按需） | + 线上难例 | 难例回流再训；必要时上 GRPO | 指标持续提升 |

## 七、评估方案与验收标准

### 7.1 评估四件套

1. **准确性**：全对率 + 单字段 Macro-F1（不均衡时主看 F1）；
2. **校准**：可靠性曲线（reliability diagram）、ECE、Brier score，按置信度分桶核对"预测置信 vs 真实频率"；
3. **泛化切片**：OOD 规则族、硬负例（1.99 vs 2.00）、无信号对照组；
4. **拒答质量**：`skip/other` 的召回率与误拒率（该拒时拒、不该拒别乱拒）。

### 7.2 门禁表（全部达标才进入转换/灰度）

| 维度 | 指标 | 门禁（建议起步线） |
|------|------|--------------------|
| 准确 | 单字段 Macro-F1 | ≥ 0.85 |
| 准确 | 全对率 | ≥ 0.90 |
| 合法 | 输出合法率 | = 1.00（约束解码保证） |
| 校准 | ECE | ≤ 0.05 |
| 校准 | Brier | ≤ 0.15 |
| 拒答 | 无信号 skip 召回 | ≥ 0.95；误拒率 ≤ 0.05 |
| 泛化 | OOD 规则族 F1 | 较同分布下降 ≤ 5 个百分点 |
| 效率 | P95 延迟 | ≤ 300ms（批服务） |

任一项不达标：回第 6 章定位（准确率→数据/训练；校准→校准集；拒答→无信号样本；OOD→切分/数据覆盖），不放行。

### 7.3 级联口径评估

上线前必须额外测**系统级**指标：加入大模型复核/人工兜底后整体准确率（目标 ≥0.96）、兜底比例（建议 ≤15%）、每千题成本、P50/P95 延迟，并做 prompt 同义改写稳定性测试（概率漂移幅度）。

## 八、格式转换与部署方案

### 8.1 三种产物的转换

```python
# ① 合并 LoRA → 16bit safetensors（vLLM/SGLang 服务）
model.save_pretrained_merged("jev-qwen35-4b", save_method="merged_16bit")
tok.save_pretrained("jev-qwen35-4b")

# ② 仅保存 LoRA 适配器（小体积、便于 A/B 与回滚）
model.save_pretrained("jev-qwen35-4b-lora")

# ③ 导出 GGUF（Ollama / llama.cpp 本地/边缘）
model.save_pretrained_gguf("jev-qwen35-4b-gguf", quantization_method="q4_k_m")
```

体积预期：BF16 约 8.4GB；Q4_K_M 约 2.74GB。**路线 B 的自定义打分头无法进入 GGUF**，需自托管（见 5.2）。

### 8.2 约束解码：从结构上保证输出合法

- **vLLM**：用 guided/structured outputs 能力，把输出约束为 `choices=["A","B","C","S"]`（或正则/CFG），只在答案位放行；
- **SGLang**：用 `choices`/约束生成接口实现等价约束，并可复用 KV 缓存做同一 state 多字段并行打分；
- **Ollama/llama.cpp**：用 grammar（GBNF）或 logit bias 把合法 token 限制在答案字符集；
- 双保险：prompt 已要求单字符，解码层再硬约束，合法率必须为 100%。

### 8.4 阈值级联（价值落地的关键）

```python
def decide(p, field):
    if field.skippable and p.argmax() == SKIP:
        return route("human", reason="no_signal")
    if p.max() >= 0.90:        return auto_execute()      # 高置信自动
    if p.max() >= 0.60:        return verify_with_llm()    # 中置信大模型复核
    return route("human")                                 # 低置信人工
```

阈值、权限、兜底全部留在确定性代码；模型只返回选项与概率。先在**可逆、低风险**节点灰度，监控分桶准确率与分布漂移。

## 十、风险分析与对策

| 风险 | 表现 | 对策 |
|------|------|------|
| 照搬 Qwen2.5 模块名 | LoRA 挂载失败/漏训 GDN 层 | 先打印 `named_modules()` 按实际名挂载 |
| thinking 未关干净 | 输出带思考、非单 token、延迟高 | 配置关闭 + 解码硬约束双保险 |
| packed 状态串扰 | GDN 循环状态跨样本泄漏 | 严格 attention 掩码，冒烟阶段先不 pack |
| 数据泄漏 | 测试虚高 | 按规则族/模板/种子分组切分，保留 OOD |
| 只准不校准 | 概率不能写阈值 | 独立校准集 + ECE/Brier 门禁 |
| 无信息硬选 | 缺字段时随机选 | 强制 15% 无信号样本 + skip 召回门禁 |
| 上游错误传导 | OCR/抽取错误被高置信选中 | 级联保留复核与日志；低置信转人工 |
| 自定义头无法转换 | GGUF 部署失败 | 默认走路线 A；路线 B 仅自托管 |
| 分布漂移 | 线上准确率下滑 | 分桶监控 + 难例回流定期再训 |

## 十一、结论与工程 Checklist

### 11.1 编号结论

1. **Qwen3.5-4B + LoRA 单 token 约束解码是性价比最高的 Jev-like 路线**，不改结构、转换部署零障碍；
2. **真正门槛是数据**：硬负例、无信号样本、按规则族切分，比调参更决定成败；
3. **校准是独立阶段**：SFT 不保证概率可用，temperature scaling 先做、ECE/Brier 门禁把关；
4. **GDN 混合架构需专门核对**：LoRA 挂载点与 packed 掩码不能照搬 Qwen2.5；
5. **价值在级联而非单点**：判别器 + 大模型 + 确定性代码 + 人工兜底，才同时拿到准确率与成本；
6. **强化非必需**：单步决策后校准通常足够，GRPO 仅在校准不达标时按需启用。

### 11.2 上线前 Checklist

- ☐ 用真实业务分布建评测集，非供应商示例
- ☐ 同时报告全对率与单字段 Macro-F1
- ☐ 含硬负例/边界样本、无信号对照组
- ☐ 校准评估：可靠性曲线、ECE、Brier，分桶核对
- ☐ 选项内置 `other/skip` 显式拒答出口，并测召回/误拒
- ☐ 关闭 thinking；解码层约束到合法字符集，合法率 100%
- ☐ LoRA target_modules 已按 GDN 实际模块名核对
- ☐ 三种产物转换验证通过（16bit / LoRA / GGUF）
- ☐ P50/P95 延迟、每千题成本、兜底比例压测
- ☐ 阈值、权限、人工兜底留在确定性代码；先灰度低风险节点
- ☐ 线上分桶监控与难例回流通道就绪
