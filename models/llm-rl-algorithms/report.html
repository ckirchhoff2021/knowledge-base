1. 背景：为什么大模型需要强化学习

导读：监督微调（SFT）解决"会照做"，但解决不了"做得好不好"和"自己探索更优解法"。强化学习（Reinforcement Learning, RL）在大模型生命周期中承担了两个不可替代的角色：对齐人类偏好、激发推理能力。

1.1 SFT 的三个天花板

大模型先经过预训练（语言建模）和监督微调（SFT，在高质量示范数据上学习），但 SFT 存在结构性局限：

  1. 只能模仿示范，无法超越示范。SFT 最小化与标注答案的交叉熵，老师多好、学生至多一样。
  2. 高质量示范成本极高。复杂推理任务（数学竞赛、代码）的标注轨迹稀缺且昂贵。
  3. "唯一正确答案"式学习无法刻画偏好。很多问题没有标准答案——帮助性、无害性、风格好坏是相对的，需要在多个候选之间比较。

1.2 RL 的两个不可替代角色

角色名称奖励来源代表事件
对齐人类偏好RLHF奖励模型 RM 对人类偏好建模2022 InstructGPT / ChatGPT（arXiv:2203.02155）
激发推理能力RLVR规则/程序自动验证答案对错（0/1）2025 DeepSeek-R1（arXiv:2501.12948）

RL 的本质区别在于：模型不再被告知"标准答案是什么"，而是自己生成多个候选、只拿到一个"好不好"的分数，然后通过试错调整生成策略。这让模型有机会探索出训练数据里没有的解法——R1 报告中观察到自我反思、验证、动态策略切换等推理行为的"涌现"。

1.3 本文与"非 RL 偏好优化"的边界

DPO（Direct Preference Optimization，arXiv:2305.18290）等方法用一个离线损失直接拟合偏好数据、无需采样和训练循环。严格意义上它们不是强化学习（没有环境交互、没有奖励、没有策略提升）。本文聚焦真正的 RL 算法，仅在对比章节简要讨论 DPO。

2. 强化学习基础：把语言生成建模为 MDP

导读：先建立"生成一个 response = 走一条轨迹"的对应关系，再推导一切大模型 RL 算法的共同祖先——策略梯度，并解释 baseline 为什么是必需的。

2.1 语言生成对应的 MDP

状态 s_t：prompt + 已生成的前 t-1 个 token
动作 a_t：第 t 个 token（动作空间 = 词表 V）
策略 πθ(a|s)：模型给出的下一 token 概率分布（即模型本身）
奖励 r_t：通常只在 response 结束时有一个总分（sparse reward）
轨迹 τ ：(s_1,a_1,...,s_T,a_T)，即一次完整生成

两个 LLM 场景的特殊性：

  1. 奖励极度稀疏。RM 通常只对完整回答给一个总分；RLVR 只有最终答案对/错（1/0）。中间 token 无即时奖励。
  2. 状态转移确定。s_{t+1} 就是把 a_t 拼到上下文得到的，没有环境随机性；全部随机性来自策略采样。

2.2 策略梯度定理：所有算法的共同祖先

∇θ J(θ) = E_{τ~πθ} [ Σ_t R(τ) · ∇θ log πθ(a_t | s_t) ]

蒙特卡洛估计（REINFORCE 基础形式）：

∇θ J ≈ (1/N) Σ_n Σ_t R(τ_n) · ∇θ log πθ(a_t^n | s_t^n)

含义直观：采样 N 条回答，得分越高的回答，其中每个 token 的概率越被提高；得分为负则压低。

2.3 为什么需要 Baseline（关键例子）

考虑 prompt「把 LLM和强化学习 中的 和 改成 -」，采样 3 个回答：

Response1（啰嗦且错误 LLM--强化学习）：R1 = 1
Response2（啰嗦但正确）：              R2 = 2
Response3（简洁正确 LLM-强化学习）：   R3 = 3

三个奖励全正，朴素策略梯度会提高所有回答的所有 token 概率——包括错误回答和废话。引入 baseline b（只要不依赖动作，梯度仍无偏），取均值 b=2：

A1 = -1（压低错误回答）｜ A2 = 0 ｜ A3 = +1（提高最优回答）

baseline 的选择是后续一切算法分野的源头：PPO 用学习的 Critic；RLOO 用"其他采样的均值"；GRPO 用组内均值；ReMax 用贪心回答奖励。

2.4 优势函数与 GAE

回报 G_t = Σ_{t'≥t} γ^(t'-t) · r_{t'}
价值 V(s) = E[G_t | s_t = s]                    # Critic 学习目标
TD 残差 δ_t = r_t + γ·V(s_{t+1}) - V(s_t)

GAE：A_t = Σ_{l≥0} (γλ)^l · δ_{t+l}
# λ 调节偏差-方差；LLM RL 中 γ 常设 1（奖励稀疏且在句末）

3. PPO：大模型 RL 的经典基线

导读：PPO（arXiv:1707.06347）是 OpenAI InstructGPT（arXiv:2203.02155）用于 RLHF 的算法，长期是事实标准。

3.1 四个模型

模型是否训练作用
Policy（Actor）✅被优化的 LLM，生成回答
Reference❄️ 冻结通常是 SFT 模型，用 KL 约束偏离程度
Reward Model❄️ 冻结对回答打分
Critic✅估计每个 token 的 V(s)，提供 baseline，通常与 Policy 同规模

Critic 与 Policy 同规模意味着至少两个同尺寸模型的训练状态，显存成本巨大。

3.2 重要性比率与 Clip 机制

ratio_t(θ) = πθ(a_t|s_t) / πθ_old(a_t|s_t)

L_PPO = E_t [ min( ratio_t · A_t,
                  clip(ratio_t, 1-ε, 1+ε) · A_t ) ]   # ε 通常 0.1–0.2
  • A_t > 0（好动作）：目标上升但超过 1+ε 后截断——鼓励但别一步到位；
  • A_t < 0（坏动作）：目标随 ratio 下降，低于 1−ε 后截断——压低即可不必压死。

clip 把每次更新限制在旧策略附近的"信任域"内，是 PPO 稳定的关键。

3.3 Critic 损失（Value Clip）

V_targ = A_t^GAE + V_old(s_t)                 # GAE 回报作为价值标签
V_clipped = V_old + clip(Vθ(s_t) - V_old, -ε_v, ε_v)
L_VF = 0.5 · max((Vθ - V_targ)^2, (V_clipped - V_targ)^2)
# LLM PPO 中通常只对 response token 计算

3.4 KL、熵与总目标

# InstructGPT：KL 惩罚加在 token 奖励里
r_t' = r_t - β · log( πθ(a_t|s_t) / π_ref(a_t|s_t) )

maximize  L_PPO - c1·L_VF + c2·E[H(πθ)]     # H 为熵，鼓励探索

3.5 训练循环与痛点

① 取 prompt，Policy 采样 response（rollout）
② RM 打分 + token 级 KL 惩罚
③ Critic 估价值，GAE 算优势
④ 多 epoch 更新 Actor / Critic
⑤ 回到 ①

痛点：① Critic 与 Policy 同规模、显存近乎翻倍；② 稀疏奖励下 Critic 难学；③ 超参高度敏感；④ 在线采样吞吐受限。

4. Critic-Free 策略梯度家族：REINFORCE → RLOO → ReMax → REINFORCE++

导读：为砍掉昂贵的 Critic，研究者用"采样回答自身的奖励统计"构造 baseline，它们是通向 GRPO 的前奏。

4.1 REINFORCE 与 REINFORCE++

REINFORCE++（arXiv:2501.03262）把 PPO 的工程技巧移植回无 Critic 的 REINFORCE：token 级 clip + 全局优势归一化（batch 内统一标准化）+ KL 正则。社区反馈（知乎·初七9527）：REINFORCE++-baseline 在长 CoT 上稳定性好；纯 REINFORCE++ 更适合 −1/1 对称奖励。定位"比 GRPO 稳定、比 PPO 快"。

4.2 RLOO：Leave-One-Out 基线

A_i = R_i - (1/(N-1)) · Σ_{k≠i} R_k

baseline 与被评价回答不相关。系统研究《Back to Basics》（arXiv:2402.14740）结论：调参得当时，简单的 REINFORCE 类方法在 RLHF 上可匹配甚至超过 PPO。

4.3 ReMax：贪心回答基线

A_i = R_i - R( greedy-decode(prompt) )     # arXiv:2310.10505

4.4 Baseline 对比

算法BaselineCritic额外开销特点
PPO价值网络 V(s)✅常驻同规模模型经典、成本最高
RLOO其他 N−1 条采样均值❌含在采样组内留一，方差小
ReMax贪心回答奖励❌1 次贪心生成简单
GRPO组内均值 + 标准化❌含在采样组内工程主流
REINFORCE++全局/组均值归一化❌含在采样组内长 CoT 稳定

5. GRPO：当代大模型 RL 的主角

导读：GRPO 出自 DeepSeekMath（arXiv:2402.03300），因 R1（arXiv:2501.12948）成为业界主流，Qwen 等大量模型采用。

5.1 核心思想：组相对优势

# 每个 prompt 从旧策略采样 G 条（如 8/16）
{o_1,...,o_G} ~ πθ_old(·|q)
μ = (1/G) Σ r_k
σ = sqrt( (1/G) Σ (r_k - μ)^2 )
A_i = (r_i - μ) / (σ + eps)

"Group Relative"：只看这条回答相对同组其他回答好不好。例如同题 4 条 {0,0,1,1}，μ=0.5，错负优、正正优，无需价值网络。

5.2 目标函数：Token 级 Clip + 显式 KL

J_GRPO = E [
  (1/|o_i|) Σ_t min( ρ_i,t·A_i, clip(ρ_i,t,1-ε,1+ε)·A_i )
  - β · KL( πθ(·|q) || π_ref(·|q) )
]
ρ_i,t = πθ(o_i,t|...) / πθ_old(o_i,t|...)

两个工程细节：① 除以 |o_i| 做长度归一化；② KL 直接写进损失而非奖励里。KL 用恒非负的无偏估计子：

KL 估计 = ρ_ref − log ρ_ref − 1 ≥ 0（令 ρ_ref = πθ/π_ref）

5.3 GRPO vs PPO

维度PPOGRPO
BaselineCritic 价值网络组内奖励均值
优势粒度token 级（GAE）回答级标量，平摊到 token
Critic需要（显存翻倍）不需要
KL 位置通常在奖励里在损失里（无偏估计）
每 prompt 采样1 条（典型）G 条

5.4 已知病理

  1. 奖励全同时优势为 0（难题全错、简单题全对）；
  2. 小 group 下方差估计噪声大；
  3. 长度偏置：token 级目标会拉长回答（尤其错误回答）；
  4. 低概率 token 的 clip 退化：关键探索 token 拿不到有效梯度。

6. GRPO 的改进变体：DAPO、Dr.GRPO、GSPO

导读：三个代表作分别修复 GRPO 的不同病理。

6.1 DAPO：四项关键技术（字节，arXiv:2503.14476）

完整开源大规模 RL 系统，Qwen2.5-32B base 在 AIME 2024 达 50 分：

  1. Clip-Higher（解耦裁剪）：正优势上界放宽（ε_high=0.28，ε_low=0.2），让低概率的关键探索 token 获得有效梯度；
  2. Dynamic Sampling（动态采样）：组内零优势时重新采样该 prompt，直到出现信号，提高有效样本占比；
  3. Token-Level Policy Gradient Loss：loss 在 batch 所有有效 token 上平均，避免短回答被长回答稀释；
  4. Overlong Reward Shaping：超长截断但已含正确答案时给软奖励而非 0。

6.2 Dr.GRPO：去长度膨胀偏置（arXiv:2503.20783）

发现 token 级长度归一化 + std 归一化的组合人为放大回答长度（尤其错误回答）；移除这些偏置源后，精简配方7B 模型 AIME 2024 达 43.3%。论文还分析了基座预训练特性对 R1-Zero 式 RL 的影响。

6.3 GSPO：序列级重要性采样（阿里 Qwen，arXiv:2507.18071）

# token 级（GRPO）：ρ_t = πθ(o_t|...) / πθ_old(o_t|...)
# 序列级（GSPO）：ρ = Π_t ρ_t = πθ(o) / πθ_old(o)

序列级裁剪、奖励与优化，训练效率更优、显著稳定 MoE 的 RL 训练，已用于最新 Qwen3。

6.4 变体对比

算法关键改动解决问题代表结果
DAPOclip-higher + 动态采样 + token loss + 软奖励零优势浪费、clip 退化32B，AIME24 50 分
Dr.GRPO去除长度膨胀偏置回答冗长7B，AIME24 43.3%
GSPO序列级 ratio/clipMoE RL 不稳用于 Qwen3

7. 奖励范式：RLHF、RLAIF、RLVR 与 R1 训练流程

导读：算法决定"怎么学"，奖励决定"学什么"。

7.1 三种奖励来源

范式奖励如何产生优点缺点
RLHF人类两两比较 → 训练 RM → 打分贴合真实偏好贵，可能被钻空子
RLAIF / CAI强模型或一组原则生成偏好廉价、可扩展继承反馈模型偏见
RLVR规则/程序验证（0/1）客观、无偏、可大规模仅限可验证任务

7.2 Reward Hacking 与奖励设计

  • KL 约束是防 reward hacking 的第一道闸；
  • 小心长度奖励/惩罚引入的偏置；
  • R1 风格规则奖励组合：
总奖励 = 正确性奖励（±1 / 0,1）
       + 格式奖励（<think>/<answer> 标签）
       + 语言一致性奖励

7.3 DeepSeek-R1 多阶段流程（arXiv:2501.12948）

R1-Zero：Base ──GRPO+RLVR──→ R1-Zero（无 SFT，纯 RL）

R1 正式路线：
① Base
② 冷启动 SFT（少量长 CoT 种子）
③ 推理 RL（GRPO + 可验证奖励）
④ 拒绝采样 + SFT（RL 产出数据，扩领域）
⑤ 全场景 RL（RM + 规则奖励）──→ R1

蒸馏：R1 推理轨迹微调小模型（1.5B–70B）

8. 核心实现伪代码

import torch

def grpo_step(prompts, policy, ref, reward_fn,
              G=8, eps=0.2, beta=0.04):
    rollouts, rewards = [], []
    # ① Rollout：每个 prompt 采样 G 条
    for q in prompts:
        outs, logp = [], []
        for _ in range(G):
            o, lp = policy.generate(q, do_sample=True)
            outs.append(o); logp.append(lp)
        r = [reward_fn(q, o) for o in outs]
        rollouts.append((q, outs, logp))
        rewards.append(torch.tensor(r))

    loss = 0.0
    for (q, outs, logp), r in zip(rollouts, rewards):
        # ② 组相对优势
        A = (r - r.mean()) / (r.std() + 1e-6)
        for o, lp_old, a in zip(outs, logp, A):
            # ③ 重要性比率
            lp_new = policy.logprob(o, q)
            rho = torch.exp(lp_new - lp_old)
            # ④ clip 目标（标量优势广播到 token）
            L = torch.min(rho * a,
                         rho.clamp(1-eps, 1+eps) * a).mean()
            # ⑤ KL 无偏估计子
            lp_ref = ref.logprob(o, q)
            r_ref = torch.exp(lp_new - lp_ref)
            kl = (r_ref - torch.log(r_ref) - 1).mean()
            loss += -L + beta * kl

    loss.backward()                      # ⑥ 更新
    policy.optimizer.step()

主流框架：OpenRLHF、verl（字节）、TRL、SLIME、NeMo-Aligner，均内置 PPO/GRPO 及变体。

9. 结论与选型建议

9.1 编号结论

  1. 一切算法源于策略梯度 + baseline，baseline 选择决定算法家族；
  2. PPO 经典但昂贵，仍是稳定工业基线；
  3. GRPO 是当代主流，工程性价比最高；
  4. 改进在消除 GRPO 的四类病理：DAPO、Dr.GRPO、GSPO；
  5. 奖励与算法同等重要，KL 是防 reward hacking 的基本手段；
  6. R1 验证纯 RL 可激发推理，模型自主涌现反思/验证行为。

9.2 工程选型 Checklist

  • ☐ 预算充足求稳：PPO（OpenRLHF/TRL）；
  • ☐ 主流推理训练：GRPO + RLVR，G 取 8–16；
  • ☐ 零优势样本多：DAPO 动态采样 + clip-higher；
  • ☐ 回答越训越长：Dr.GRPO；
  • ☐ MoE RL 不稳：GSPO；
  • ☐ 长 CoT、group 小：REINFORCE++-baseline；
  • ☐ 监控：reward、长度、entropy、KL、clip fraction、零优势比例；
  • ☐ 门禁同时覆盖目标提升与通用能力不退化；
  • ☐ rollout/训练分离（vLLM + FSDP/Megatron），解决生成吞吐瓶颈。
