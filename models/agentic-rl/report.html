1. 背景：从单轮 RLVR 到 Agentic RL

导读：2025 年初 DeepSeek-R1 证明单轮可验证奖励（RLVR）能激发数学/代码推理；2025 下半年到 2026 年，主战场转向让模型在真实环境中多轮行动——Agentic RL。

1.1 范式转移：从"答题"到"做事"

GRPO + RLVR 优化的是一次性生成：给题、输出思维链与答案、验证器判对错、回合结束。真实智能体任务则是：

观察状态 → 思考 → 调用工具（搜索/代码/浏览器/终端/API）
        → 拿到环境反馈 → 再思考 → 再调用 …（多轮）
        → 最终只有任务成功/失败一个稀疏信号

典型场景：网页购物（WebShop）、文本具身（ALFWorld）、多跳搜索问答、软件工程（修真实 GitHub issue）、多步数据分析。模型必须学会何时调用工具、调用什么、如何根据反馈修正、何时停止。

直觉类比：单轮 RLVR 像闭卷考试，交卷即出分；Agentic RL 像完成真实课题——查资料、做实验、失败重来、管理预算，几周后才知道成败。难点从"解题"变成"在不确定环境里持续做正确决策"。

知乎高赞综述（Snail，266 赞）总结的最重要行业信号："不是又出现了一个更好的 PPO/GRPO 变体"，而是有效的 Agentic RL 已从单轮文本优化，转向长上下文、工具调用、部分可观测、异步执行环境中的系统性策略学习。

2. 问题定义：Agentic RL 与单轮 RL 的五个本质差异

2.1 轨迹成为优化单位

τ = (s_0, a_0, o_0, s_1, a_1, o_1, ..., s_T, a_T, R_final)

动作 a_t 既可能是推理 token，也可能是工具调用；环境 observation 进入下一步状态。优化目标是整条轨迹的期望回报。

2.2 五个本质差异

维度单轮 RLVRAgentic RL
回合结构一问一答多轮观察–思考–行动–反馈
奖励答案对错，回合末给出极稀疏且延迟，常仅最终成败
环境无（验证器是纯函数）有状态、有随机性、可能不可逆
轨迹长度数百–数千 token，秒级数千–数万 token，分钟–小时级
数据分布近似 on-policy天然 off-policy / stale

多数环境是 POMDP：策略只看得到 observation history。策略梯度定理形式不变，但估计每一步都变难：方差爆炸（一个 0/1 归因上万 token）、环境方差混入、信用分配困难。

3. 核心挑战：多轮环境下的七类病理

3.1 稀疏奖励与长程信用分配

朴素做法把轨迹级优势平摊给所有 token——成功了奖励全部动作、失败了惩罚全部动作，无关与错误动作得不到区分。这是 GiGPO、SPA-RL 的出发点。

3.2 回声陷阱（Echo Trap）与训练崩溃

RAGEN（arXiv:2504.20073）发现：训练中反复出现奖励方差骤降（variance cliffs）伴随梯度尖峰（gradient spikes），成功率突然崩掉。机理是策略与环境形成正反馈回路，模型输出容易触发环境固定回应的模式，rollout 不断"回声"自我强化。T²PO（ICML 2026 Spotlight，arXiv:2605.02178）同样报告强 baseline 在不同种子下出现 success rate 下降、KL 与梯度范数爆炸。

3.3 模板坍塌（Template Collapse）

RAGEN-2（arXiv:2604.06268）命名的隐蔽病理：模型表面推理格式多样，实际依赖与输入无关的固定模板。论文用基于互信息的诊断框架识别这种"伪多样性"。

3.4 犹豫与无效轮次

T²PO 的观点"犹豫就会败北"：模型持续生成既不降低不确定性、也不推进任务的低信息内容，空转 rollout 预算、放大噪声。SimpleTIR（arXiv:2509.02479）直接过滤含无效轮次的轨迹。

3.5 Reasoning 与 Tool-use 的梯度冲突

人大与字节（arXiv:2602.00994）用 LEAS 量化发现：推理 token 与工具调用 token 的梯度方向"打架"——推理要支持深入推导，工具调用要支持准确格式化与选择，在共享参数空间互相干扰；"联合训练可和平共处"的隐含假设从未被系统验证。

3.6 交互坍塌（Interaction Collapse）

ASTER（arXiv:2602.01204）发现扩展工具推理时工具调用频率不升反降，模型退回"纯思考"舒适区（短交互轨迹方差小、梯度更稳）。需用高交互密度轨迹冷启动避免。

3.7 分布偏移：Staleness 与 Train-Serving Mismatch

分钟级 rollout 采完时，旧策略已落后多个更新版本，重要性采样比率极端化；工具环境本身也在变（搜索索引、网页结构），训练分布与部署分布持续偏移。

七类病理总表

4. 算法方案谱系

导读：算法工作可归四族：轨迹级框架、细粒度信用分配、探索/稳定控制、参数解耦。

4.1 轨迹级框架：StarPO

RAGEN 提出 StarPO（State-Thinking-Actions-Reward Policy Optimization），以整条轨迹为优化单位；稳定变体 StarPO-S 抑制回声陷阱中的梯度尖峰。它确立了"loss 对象是 trajectory"的基本范式。

4.2 细粒度信用分配

GiGPO：组中组（arXiv:2505.10978）

外层组：同一 task 采样多条完整轨迹（同 GRPO）
内层组：每个时间步 t，跨轨迹收集"同状态下"的动作
        → 用步级组内相对量估计细粒度优势

评估"第三步好不好"看的是相同状态步上这步动作相对其他轨迹同步动作的表现，保持 critic-free、低内存、稳定收敛。

SPA-RL：逐步进展归因（arXiv:2505.20732）

把最终奖励再分配为反映每一步增量贡献的中间奖励，让多步交互获得密集的进展信号。

4.3 探索控制与训练稳定

  • ARPO（arXiv:2507.19849）：基于熵的自适应采样，在全局推理与局部工具交互间动态分配资源，一半工具调用预算取得更优性能；
  • T²PO（arXiv:2605.02178，ICML 2026 Spotlight）：监控每步不确定性，抑制"犹豫"式低信息生成，把预算导向有信息量的行为，稳定多轮训练；
  • SimpleTIR（arXiv:2509.02479）：即插即用地过滤含无效轮次的轨迹，并鼓励多样推理模式。

4.4 参数解耦：DART 双 LoRA（arXiv:2602.00994）

给推理和工具使用各配一个独立 LoRA 适配器，两条梯度路径互不干扰，用单模型（共享底座 + 双适配器）达到"推理模型 + 工具模型"双系统的效果。

5. 学习信号：环境、奖励与课程

5.1 可验证环境规模化

  • 软件工程：真实仓库 + issue + 隐藏测试，SWE-Universe（arXiv:2602.02361）把环境扩到百万量级；
  • 工具沙箱：代码解释器、浏览器、终端，动作真实执行、结果可判；
  • 模拟环境：ZeroSearch 用模型模拟搜索返回，训练后迁移到真实工具；
  • 风格化环境：WebShop、ALFWorld 用于受控研究。

5.2 奖励设计的层次

结果奖励：任务成功（0/1）、测试通过 —— 最稀疏但最客观
过程/格式奖励：调用格式正确、参数合法
效率奖励：调用次数 / token 预算（OTC）
进展奖励：SPA-RL 式步级增量归因

ToolRL 的结论"Reward is All Tool Learning Needs"——好的奖励原则比复杂算法更关键。

5.3 冷启动与课程

  • ASTER：冷启动轨迹须高交互密度，防止一开始就不调工具；
  • ICLR 2026 lightweight SFT 研究：为 RL 做准备只需轻量 SFT，过度 SFT 压缩探索空间；
  • Kimi K2：大规模 agentic 数据合成管线自动构造带工具交互的轨迹。

6. 基础设施：异步数据流与大规模训练系统

6.1 三难权衡

MiniMax Forge 把核心矛盾总结为：吞吐 × 稳定性 × agent 灵活性不可兼得。等采完再训稳定但 GPU 闲置；边采边训吞吐高但 stale 严重。

6.2 五项关键技术

  1. Partial Rollout Reuse（Kimi k1.5，arXiv:2501.12599）：策略更新后不丢弃未完成轨迹，配合 mirror-descent 式优化重用片段；k1.5 摘要明确把长上下文扩展与改进策略优化（含 partial rollout）列为关键，且不依赖 MCTS/价值函数；
  2. 异步调度、Actor–Rollout 分离：训练与 vLLM 类生成引擎解耦（SkyRL，arXiv:2511.16108）；
  3. 蜂群弹性伸缩：通义 AgentJet 按 rollout 负载动态扩缩生成资源；
  4. Agent Swarm / PARL（Kimi K2，arXiv:2507.20534）：K2（1T 总参/32B 激活 MoE）联合 RL 阶段用智能体集群产交互数据；MuonClip 优化器（Muon + QK-clip）使其 15.5T token 预训练零 loss spike；
  5. Staleness 控制：限制 rollout 落后版本数、过旧轨迹降权、token 级 clipping。

7. 前沿系统实战：Kimi、MiniMax、GLM 路线对比

系统核心打法代表性技术
Kimi k1.5/K2/K2.5简洁 RL 框架 + 大规模 agentic 数据partial rollout、长上下文 RL、MuonClip、agentic 数据合成、Agent Swarm、token 级 clipping；K2.5 扩展到视觉 agent
MiniMax M1/Forge效率优先的 test-time 扩展 + agent RL 框架Lightning Attention 降长程成本；Forge 直面吞吐×稳定×灵活三难
GLM-5阶段化 RL pipelineReasoning RL → Agentic RL → General RL 顺序推进；异步基础设施 + 跨阶段蒸馏

阶段化 RL 特别值得注意：它反对三种能力混在一个阶段训完（与 3.5 梯度冲突同源）——先纯推理 RL，再工具交互，最后通用偏好对齐，阶段间蒸馏传递能力。这与 DART 是同一矛盾的两种解法：时序解耦 vs 结构解耦。

8. 统一视角：三大不变量与工程 Checklist

三大不变量（有效 Agentic RL 必须始终维持）
  1. 探索不塌缩：可探索空间不能过早收敛——高交互冷启动、熵监控、自适应采样；
  2. 梯度非退化：持续制造优势不坍缩的批次——动态采样、无效轨迹过滤、细粒度信用分配；
  3. 分布可控：控制更新与部署间偏移——partial rollout、staleness 过滤、token 级 clip。

工程选型 Checklist

  • ☐ 先问任务是否真需要多轮：单轮 RLVR 能解的不要上 Agentic RL；
  • ☐ 环境三要素：可大规模并行、动作可执行可回滚、结果可客观验证；
  • ☐ 冷启动保证工具交互密度，SFT 宁轻勿重；
  • ☐ 长程任务优先试 GiGPO 或 SPA-RL，不要把轨迹 0/1 平摊；
  • ☐ 训练看板：奖励方差、熵、工具调用频率、有效轮次占比、梯度范数、KL、轨迹多样性；
  • ☐ 对症：回声/崩溃→StarPO-S/T²PO；空转→SimpleTIR；工具越用越少→高交互冷启动；想做冲突→DART/阶段化 RL；
  • ☐ 基础设施：actor/rollout 分离 + 异步调度 + partial rollout + staleness 上限；
  • ☐ 效率约束进奖励（调用次数/token 预算）；
  • ☐ 评估必须分能力：成功率之外，单独评估推理与通用能力是否退化。
