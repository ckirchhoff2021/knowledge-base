0. 摘要（TL;DR）

「记忆」正在成为 2025–2026 年大模型智能体（Agent）栈中增长最快、也最被低估的独立基础设施层。 三年前，给 LLM 加「记忆」约等于把对话历史塞进上下文窗口；而到 2026 年，记忆已经拥有自己的学术分类、自己的基准套件（LoCoMo / LongMemEval / BEAM / DolphinBench / STATE-Bench）、自己的开源生态（Mem0 GitHub 星标在 2026 年已突破 6 万）和清晰可量化的架构差距 [4][9][10][26]。2025 年 12 月，综述《Memory in the Age of AI Agents》（arXiv:2512.13564）发布当天登上 Hugging Face Daily Papers 第一名，标志着「智能体记忆」从零散技巧沉淀为一个正式研究领域 [2][27]。

本报告的核心判断：

  1. 无状态（stateless）是当前 LLM 的原生缺陷，而非可选项。 智能体在生产环境会同时遭遇三类性质不同的记忆失败：会话重置（session reset，每次对话从零开始）、知识缺口（knowledge gap，训练截止后 / 内部系统的知识无法获取）、学习泄漏（learning leak，本轮交互中得到的纠正与偏好在会话结束后蒸发）。朴素 RAG 只能解决第二类 [2][27]。
  2. 记忆不是检索问题，而是一个有完整生命周期的系统资源。 权威综述沿「形式 × 认知功能 × 动态性」三个正交轴组织记忆：形式上分为参数记忆（权重）、激活记忆（KV-Cache）、外部记忆（文本 / 图）；认知功能上分为工作 / 情景 / 语义 / 程序四类；动态性上关注读、写、更新、矛盾消解与遗忘 [1][2]。
  3. 技术谱系已演化出六条可辨识的路线：① 全上下文 / 朴素 RAG 基线；② 摘要压缩（ReadAgent）；③ 操作系统式分层分页（MemGPT / Letta）；④ 事实抽取（Mem0）；⑤ 双时序知识图谱（Zep / Graphiti）；⑥ 自组织 / 自进化的 Agentic 记忆（A-MEM、HippoRAG、EM-LLM、MemOS）[3][4][5][6][7][8][11][15]。
  4. 最本质的工程权衡是「写时压缩 vs 读时保留」：Mem0、Claude Code Auto Memory 在写入时积极抽取压缩，换取小上下文与低成本，但抽取误差会随时间累积；MemMachine 等保留原始片段、在读时重判，事实完整性更高但检索更重；Zep 走第三条路——写入时抽取，但用显式时间有效期让过期事实自动失效 [27][28]。
  5. 2026 年的研究前沿收敛到四个开放问题：自进化 / 可学习记忆（用未来检索质量作奖励去学习「该记什么」，如 Evo-Memory、CHIME、MindMemOS）[22][23][24]、程序记忆（让 Agent 改写自身行为规则，复利价值最高却最不成熟）、多智能体记忆协调（谁拥有、如何合并群体记忆）、隐私与记忆抽取攻击（记忆层是一个尚未被充分防护的新攻击面，有 GDPR 含义）[20][26][27]。

1. 为什么是现在：无状态 LLM 的三重失败与一场「层」的独立

1.1 LLM 天生「无状态」

一次标准的 LLM 调用是纯函数：给定输入 token，返回输出 token，模型权重在推理期不发生任何持久改变。这意味着模型本身没有跨请求的记忆——它「记得」的一切，要么冻结在参数里（训练语料的统计痕迹），要么必须由调用方每次重新放进上下文窗口。当模型只做单轮问答时这不是问题；但当它以智能体身份在真实环境中多轮执行、跨天 / 跨项目持续工作时，无状态就从学术特性变成了工程事故源 [2][26]。

1.2 三类被长期混为一谈的记忆失败

《Memory in the Age of AI Agents》综述与生产实践共同指出，「记忆问题」其实是三个正交问题，最常见的错误就是把它们当成一个问题来解决 [2][27]：

失败模式 现象 朴素 RAG 能否解决 典型受害场景
会话重置 Session reset 每次新对话上下文窗口空白，用户被迫重复上周已交代过的背景 部分（需把历史入库） 编码 Agent 数周内习得的代码库「行话」在会话边界丢失
知识缺口 Knowledge gap 无法访问训练截止后、或只存在于内部系统的组织 / 领域知识 ✅ 直接解决（查询时检索文档） 企业知识问答、最新政策 / 价格
学习泄漏 Learning leak 交互中产生的纠正、偏好、教训（「这里我们偏好异步」「这个 API 有已知延迟坑」）随会话结束蒸发 ❌ 不解决（RAG 索引文档，不捕获交互中生成的知识） 几乎所有已部署的企业 Agent

关键洞察是：RAG 索引的是「文档」，而不是「交互中产生的新知识」。第三类失败——学习泄漏——正是大多数企业 Agent 部署至今没有答案的地方，也是 Mem0、A-MEM、Letta 等系统的主战场 [5][27]。

1.3 从 Prompt Engineering 到 Context Engineering，记忆成为独立一层

2025 年以来，业界普遍用「上下文工程（Context Engineering）」取代「提示词工程」来描述 Agent 设计：核心任务不再是写一句巧妙的 prompt，而是系统化地管理「此刻该让模型看到什么信息」。记忆层正是上下文工程中负责跨时间持久化与召回的子系统 [27][28]。

其独立性也得到市场数据佐证：Mem0 在《State of AI Agent Memory 2026》中引用 Gartner 预测——到 2026 年底将有 40% 的企业应用集成任务型 AI Agent（2025 年这一比例不足 5%）；麦肯锡 2025 年全球 AI 调研则显示 23% 的组织已在至少一个业务职能规模化部署 Agentic 系统。记忆「坐」在这条采纳曲线的正后方：一个无法跨会话保持上下文的 Agent，在真实生产工作流中无法存活 [26]。

2. 认知分类学：三个正交轴与四类记忆

要理解纷繁的记忆系统，最有效的方式是采用权威综述给出的多轴分类，而不是罗列产品名 [1][2]。

2.1 形式轴（Form）：记忆「住在哪里」

  • 参数记忆（Parametric）：编码在模型权重中的知识。容量巨大但更新昂贵、不可精确删除（这也是「被遗忘权」在 LLM 上的难题）。
  • 激活记忆（Activation）：推理时的 KV-Cache / 隐状态。速度最快、容量受上下文窗口与注意力衰减约束。
  • 外部记忆（External）：上下文之外的文本、向量、图、数据库。可精确增删改查、可审计，是当前工程系统的主体。

MemOS 的核心主张正是把这三类记忆当作同一种「一等资源」统一治理，而大多数框架只能管理外部记忆 [6]。

2.2 认知功能轴（Cognitive Function）：这是「哪种」记忆

这一轴直接映射认知科学，对系统设计最具指导意义 [2][26]：

记忆类型 对应人类记忆 存什么 代表实现 成熟度
工作记忆 Working 工作记忆 / 当下注意 当前系统指令、工具 schema、最近若干轮 上下文窗口本身 高
情景记忆 Episodic 海马体 / 亲身经历 「发生了什么、按什么顺序、结果如何」，带时间与任务标记 Generative Agents 记忆流 [12]、EM-LLM [8]、A-MEM 笔记 [5] 中高
语义记忆 Semantic 通用事实与概念 与习得事件解耦的事实、偏好、关系、领域规则 MemoryBank [13]、Mem0 事实库 [4]、Zep 图谱 [7] 高
程序记忆 Procedural 技能 / 肌肉记忆 「怎么做」：工作流、工具使用习惯、评审规范、部署步骤 Letta 自改 core memory、LangMem、ExpeL [17]、Voyager 技能库 [18] 最低 / 价值最高

一个被反复验证的经验结论是：语义记忆增强对小模型收益最显著，而更强的模型从情景记忆中获得的边际价值更高 [2][27]。程序记忆则是长期复利所在——一个能学会「避免反复修过的某类 bug」「内化团队 code review 约定」的 Agent，其价值会随时间复合增长，但目前只有极少数框架（Letta、LangMem）真正支持 Agent 改写自身行为指令 [27]。

2.3 动态轴（Dynamics）：记忆如何随时间变化

记忆不是只写一次的日志，而是需要读（retrieve）、写（write / consolidate）、更新（update）、矛盾消解（contradiction resolution）、遗忘 / 过期（expire / forget）的动态对象。「价格从 €299 改成 €399」这类事实演化，恰恰是只做 ADD 的向量库最薄弱的地方——它会同时保留两条互相矛盾的事实，直到下一次抽取碰巧触发 UPDATE [2][27]。

2.4 与人类记忆系统的对应

神经科学为该领域提供了大量隐喻与机制：HippoRAG 直接模拟海马体（hippocampus）在新皮层中进行单跳 / 多跳知识关联的模式，用个性化 PageRank 在知识图上检索关联事实 [11]；EM-LLM 用注意力做事件边界检测（event boundary detection），其切分与人类感知的情景分段相关，从而支持高达千万 token 的检索 [8]；A-MEM 则借用社会学家 Niklas Luhmann 的 Zettelkasten（卡片盒笔记法），用原子笔记 + 双向链接让记忆自组织成网 [5]。

3. 技术谱系：六代记忆架构

下面按「记忆如何组织、谁来决定读写」这条主线，拆解六代（含若干旁路）架构。它们并非严格的替代关系——2026 年的生产系统通常是多代的组合 [26]。

3.1 第一代：全上下文与朴素 RAG（基线）

  • 全上下文（full-context）：把全部历史塞进窗口。LoCoMo 上约需 1.6 万 token / 对话，长程场景可达 2.6 万 token 以上，成本高且受「中间遗忘」（lost-in-the-middle）影响 [4][9]。
  • 朴素 RAG：文档切块、嵌入、相似度检索、塞进 prompt。它解决知识缺口，却不捕获交互知识，也没有更新 / 有效期概念。

3.2 第二代：摘要 / 要点压缩（ReadAgent）

ReadAgent（A Human-Inspired Reading Agent with Gist Memory，arXiv:2402.09727）受人类「先存要点、必要时回看原文」启发，把长文本切成小段并存「gist（要点）」，检索时先定位要点再回看相关原文，以小模型即可处理超长上下文 [15]。这是「写时压缩」思想的早期代表。

3.3 第三代：操作系统式分层分页（MemGPT / Letta）

MemGPT（arXiv:2310.08560）是范式转折点：它把操作系统的内存层级搬到 LLM 上 [3]——

  • Core memory（核心记忆）：始终在上下文内，相当于 RAM，又分「人设（persona）」与「人类（human）」两块；
  • Recall memory（召回记忆）：可搜索的完整对话历史，相当于磁盘缓存；
  • Archival memory（归档记忆）：外部可检索向量库，相当于大容量磁盘。

Agent 通过显式函数调用（core_memory_append/replace、archival_memory_insert/search、conversation_search）自行在层级间换页（paging），从而让有限上下文窗口「表现得」像拥有无限记忆。其商业化实体 Letta 是少数让记忆决策对模型透明、可在推理轨迹中审计的框架，也是少数具备真正程序记忆（Agent 可改写自身 core memory）的系统 [3][27]。代价是 Agent 必须额外消耗推理步骤来管理自己的记忆，延迟与编排复杂度更高。

MemGPT 的分层思想在 2026 年已成为行业通用语：Mem0 官方文档也把「工作记忆（上下文）+ 语义存储 + 实体链接」描述为同一套层级，而非五选一 [26]。

3.4 第四代：事实抽取与 ADD/UPDATE/DELETE（Mem0）

Mem0（arXiv:2504.19413，ECAI 2025）是当前应用最广的记忆框架，其论文首次在 LoCoMo 上对十种方法（文献基线、开源工具、RAG、全上下文、OpenAI Memory、Zep 等）做了统一横评 [4]。其机制是：每轮对话后，用一个抽取模型判断哪些事实值得保留，并对混合「向量 + 键值」存储发出 ADD / UPDATE / DELETE / NOOP 操作；可选图模式（Mem0g）再加入有向带标签图做实体关系建模。

论文报告（厂商口径，引用时需注意）：相对 OpenAI 原生记忆准确率提升约 26%，中位延迟约 0.71 秒，并节省约 90% 的 token [4][29]。其结构性短板是时间推理：事实默认不带有效期，两条冲突事实只能等下一次抽取触发 UPDATE 时才被消解，而不是在现实变化时自动失效 [27]。

2026 年 4 月 Mem0 发布新算法，两个关键变化是：单遍 ADD-only 抽取（把 Agent 自己确认 / 推荐的事实与用户陈述的事实同等对待）与多信号检索（语义相似度、BM25 关键词、实体匹配三路并行打分并融合）；官方在 LoCoMo / LongMemEval 上分别报告 92.5 / 94.4 分、约 6900 token / 查询，时间类查询提升 +29.6 分、多跳推理 +23.1 分（均为厂商自测，已开源评测框架）[26]。

3.5 第五代：双时序知识图谱（Zep / Graphiti）

Zep（arXiv:2501.13956，《Zep: A Temporal Knowledge Graph Architecture for Agent Memory》）走了一条根本不同的路：每条事实都被存成带显式起始 / 结束有效期（bi-temporal，双时间轴）的图节点 [7]。「客户 X 预算 €50 万」不是一个扁平字符串，而是一个有时间边界的命题，被新事实取代时自动失效。检索融合语义搜索、BM25 关键词与图遍历。

对于事实天然带保质期的领域（病历、CRM、合规状态、合同时效、动态定价），双时序模型在结构上优于无时间维度的 Mem0；代价是更复杂的图基础设施与更高写入延迟。其开源图引擎为 Graphiti（注意：arXiv:2504.03182 题为 "Graphiti" 的论文是一个无关的图 / 关系数据库查询工作，并非 Zep 的 Graphiti，本报告不据其立论）[7][27]。

3.6 第六代：自组织 / 自进化的 Agentic 记忆

第六代的共同主张是：记忆的结构与读写不应由开发者预先写死，而应由 Agent 在运行中自主生成、连接、演化。

  • A-MEM（arXiv:2502.12110，NeurIPS 2025）：遵循 Zettelkasten 卡片盒法。每条新记忆经 LLM 构造成一张含「原始内容 c、时间戳 t、关键词 K、标签 G、上下文描述 X、嵌入向量 e、链接集 L」的结构化原子笔记；先按嵌入召回 top-k 近邻，再由 LLM 判断是否建立链接（Link Generation），并据此演化（Memory Evolution）旧笔记的关键词 / 标签 / 描述——新经验会反向更新旧记忆，使网络持续自我精炼。在 LoCoMo 上对六个基座模型一致优于 LoCoMo 基线、ReadAgent、MemoryBank、MemGPT，且平均 token 长度从约 1.69 万降到约 1100–2500 [5]。
  • HippoRAG（arXiv:2405.14831）：模拟海马体，把多跳问答变成知识图上的 Personalized PageRank 检索，在多跳任务上显著优于朴素 RAG，并逼近更强的上层模型 [11]。
  • EM-LLM（arXiv:2407.09450）：用预测事件边界的机制切分长经验，支持跨千万 token 的情景检索，在 LongBench 与 ∞-Bench 上优于 RAG 与全上下文 [8]。
  • MemOS（arXiv:2505.22101）：最具野心的「记忆操作系统」，把参数记忆、激活记忆（KV-Cache）、外部记忆统一为一等资源做全生命周期治理；其 Cloud 插件通过多 Agent 共享统一记忆池，在 LOCOMO 上把总 token 从约 1560 万降到约 440 万（约 -72%，论文口径）[6]。
  • Cognitive Workspace（arXiv:2508.13171）：区分主动策展与被动检索，用层级化认知缓冲 + 任务驱动的上下文优化实现「功能型无限上下文」，记忆复用率达 58.6%（传统 RAG 为 0%）[19]。

此外，Generative Agents（arXiv:2304.03442） 的「记忆流（memory stream）+ 重要性打分 + 周期性反思（reflection）」是几乎所有后续工作的思想源头之一 [12]；SCM（arXiv:2304.13343） 用记忆流 + 控制器自主决定何时存取 [14]；MemoryBank（arXiv:2305.10250） 引入基于艾宾浩斯遗忘曲线的记忆更新 [13]。

4. 记忆从哪来、怎么存、如何被取回：一条完整生命周期

把六代架构拆开看，任何记忆系统都在回答四个问题。

4.1 写入（Encoding / Write）

  • 写什么：全量历史（全上下文 / MemoryBank）还是抽取后的原子事实（Mem0 / A-MEM）。
  • 谁决定：工作流里预先写死存储点（传统系统），还是 Agent 用函数调用自主决定（MemGPT / Letta、A-MEM）。
  • 抽取代价：LLM 抽取本身会出错。激进压缩派（Mem0、Claude Code）写入成本低，但一次错误的 ADD/UPDATE 会作为小幅事实偏差持续累积；原始保留派（如 MemMachine）存原始片段、读时再判，事实更保真但检索更重 [27]。

4.2 组织与存储（Organization / Storage）

  • 扁平文本 / Markdown：Claude Code 的 7 层记忆全部是 git 可版本化的 Markdown，零运维、可审计、可 diff，但用关键词检索、无时间建模、有载入行数上限 [27]。
  • 向量库：语义召回主力，Qdrant / Chroma / Weaviate / Milvus / PGVector 等是常见后端；Mem0 在 2026 年已支持约 20 种向量 / 图存储 [26]。
  • 知识图谱：实体关系建模（Mem0g、Zep、HippoRAG），擅长多跳与关系推理。值得注意的是 Mem0 2026 新算法用内建实体链接取代了外部图存储——实体只参与排序加权、不再可直接遍历，对需要图查询的团队是功能回退，对只想免运维获得实体感知的团队是净收益 [26]。

4.3 检索（Retrieval）

从单一向量相似度，演进为语义 + 关键词（BM25）+ 实体 / 图遍历的多信号融合，并普遍加一层 reranker 重排 [26]。检索还需处理作用域（scope）：Mem0 的 user_id / agent_id / run_id(session) / app_id(org) 四级作用域可组合，配合元数据过滤实现多租户隔离 [26]。

4.4 更新、矛盾消解与遗忘（Update / Consolidation / Forget）

这是区分「玩具」与「生产系统」的关键环节：

  • 操作语义：Mem0 的 ADD/UPDATE/DELETE；A-MEM 的记忆演化会改写旧笔记 [4][5]。
  • 时间失效：Zep 的双时间轴让过期事实自动失效 [7]。
  • 巩固 / 做梦（consolidation）：Claude Code 的 Auto Dream 后台进程把模糊时间词替换成确切日期、按当前真值消解矛盾、剪枝已删文件引用、把反复出现的模式提升为长期规则——类比生物睡眠中的记忆巩固与缓存 TTL [27]。
  • 遗忘曲线：MemoryBank 借艾宾浩斯曲线决定记忆强化时机 [13]。

4.5 一条贯穿始终的原则：「是提示，不是事实」

Claude Code Auto Memory 最重要的安全设计是要求模型把记住的内容当作提示（hint）而非事实（fact），在据此行动前回到真实代码 / 权威数据源核验。这种「放心记、行动前先验证」的非对称信任，能系统性降低「因记忆陈旧而大规模幻觉」的风险，应作为所有记忆系统的默认范式 [27]。

5. 评测体系：基准、指标与「数字不可直接比较」

记忆领域 2024 年才开始有可复现的标准基准，此前多为自报。当前五个主流基准各测一面，没有任何单一基准能给出通用分数 [9][10][26]：

基准 测什么 记忆跨度 评测方式 主要局限
LoCoMo（arXiv:2402.17753）[9] 单跳 / 多跳 / 时间 / 开放域 / 对抗类对话回忆 多会话（均约 9K token、最多 35 会话、7512 问答对） F1 + BLEU + LLM 裁判 主要是对话 QA
LongMemEval（arXiv:2410.10813）[10] 知识更新、时间推理、多会话 / 偏好回忆（6 类） 长历史 准确率 + LLM 裁判 应用级动作覆盖弱
BEAM 1M / 10M token 规模下的召回与推理（10 类） 极长对话 分类准确率 评测成本高，无法靠扩窗口解决
DolphinBench 记忆是否真正改善工具调用的动作与结果 多年模拟历史 任务完成度 / 成本 / 延迟 较新、已测系统少
STATE-Bench 重复企业工作流中 Agent 是否因经验而变好 重复工作流 任务表现 企业场景较窄

五个常用度量维度需同时看，避免单点优化：BLEU / F1（token 级）、LLM 裁判分、token 消耗 / 查询、延迟。一个准确率高但每查询要 2.6 万 token 的系统并不具备生产可行性 [26]。

为什么两个实验室跑同一基准会得到不同分数？ 至少有十几个变量在起作用：数据集版本、灌入方式与延迟、记忆系统版本、答题模型、top-k 检索深度、是否重排、prompt 格式、LLM 裁判宽严、只评召回还是端到端、如何处理冲突记忆、token 与延迟的记账口径等。因此——一个没有附带方法说明的数字只是声明，不是结果；横评时应对齐基准版本与范围并索要评测代码 [26]。厂商自报分数（如 Mem0、Zep 文档中的数字）天然偏向厂商自身，本报告在引用处均已显式标注口径。

6. 生产级系统横向对比与选型

下表汇总主流系统在企业落地最关心维度上的结构性差异（综合官方资料与第三方工程评测，星标 / 下载量为 2025 年末至 2026 年的公开口径，随时间变化）[4][7][26][27]：

系统 存储范式 时间有效期 人可编辑 / 审计 程序记忆 陈旧信息管理 最适合
Claude Code（CLAUDE.md + Auto Memory） 扁平 Markdown，git 版本化，7 层作用域 ✗（Auto Dream 事后补日期） ✓ 一等公民 ~ 靠常驻规则，不能自改写 后台 Auto Dream 巩固（尽力而为） 编码 Agent、团队协作、零运维
Mem0 / Letta 前身生态 向量 + 键值 +（可选）图 / 实体链接 ✗ 默认无有效期 ~ 通过 API 操作 ✗ 抽取冲突时 ADD/UPDATE/DELETE 个性化、消费级 SaaS、高并发偏好
Zep / Graphiti 双时序知识图谱 ✓ 每事实显式起止有效期 ~ 图 API ✗ 被取代时自动时间失效 CRM、病历、合规、合同时效
Letta（MemGPT） core（在上下文）+ archival（向量）+ recall（历史） ~ Agent 自管时间戳 ✓ 推理轨迹中可检视记忆块 ✓ Agent 可改写自身 core memory Agent 通过显式工具调用决定 自主长时运行、需自管记忆的 Agent
MemOS 参数 + 激活 + 外部统一治理 ✓ 全类型生命周期 ~ Memory Viewer 控制台 ✓ 工具记忆 / 技能演化 调度 + LLM 引导巩固 自托管企业、多 Agent 记忆共享
A-MEM 自组织原子笔记 + 双向链接网络 ~ 笔记可演化 ✓ 笔记含可读属性 ~ 通过演化间接调整 新记忆触发旧记忆演化 需要灵活、跨任务泛化的研究型系统

选型决策框架（来自生产模式归纳）[27]：

  1. 编码 / 团队协作：先用 Claude Code 原生 Markdown 栈，零运维；只有在出现可复现的检索失败后再升级。
  2. 个性化 / 消费 SaaS：Mem0，生态最成熟、MCP 与多框架支持最全；接受其时间建模短板为已知约束。
  3. 事实随时间变化：Zep / Graphiti，双时序是正确原语，领域事实变化越快优势越大。
  4. 自主长时运行 Agent：Letta，唯一让 Agent 拥有记忆决策权且全程可审计。
  5. 高并发多 Agent / 自托管：MemOS，跨类型统一治理 + 多 Agent 共享省 token。
  6. 事实准确性至上（研究阶段）：原始片段保留路线（如 MemMachine 类），以检索复杂度换抽取误差不累积。

工程落地还应遵循七条 checklist：先原生后升级、在写入第一条事实前定义陈旧度策略、普遍采用「提示不是事实」、像源码一样给记忆打版本 / 快照、上线前用时间对抗性问题压测、把记忆访问当作安全边界、多智能体在 spawn 第一个子 Agent 前就定好记忆归属（共享命名空间 vs 隔离 + 合并策略）[27]。

7. 前沿趋势（2026）：四个开放战场

7.1 自进化 / 可学习记忆（Self-Evolving Memory）

这是 2025 年末以来最活跃的研究线程。当前抽取式系统在写入时用固定启发式判断「什么看起来重要」；自进化系统则用未来的检索 / 任务结果作奖励，去学习「什么在将来真正用得上」，从而有望弥合「写时压缩 vs 读时保留」两派 [27]。2026 年的代表性新工作：

  • Evo-Memory（arXiv:2511.20857）：把记忆系统当作评测 Agent「测试时学习（test-time learning）」能力的基准与框架，衡量自进化记忆能否随交互持续变强 [22]。
  • CHIME（arXiv:2609.02074）：面向长程 Agentic 规划的「信用感知层级记忆演化（Credit-Aware Hierarchical Memory Evolution）」，把经验的好坏信用归因到记忆条目并层级化更新 [23]。
  • MindMemOS（arXiv:2608.12428）：可移植、自进化的「记忆操作系统层」，强调跨模型 / 跨应用携带记忆 [24]。
  • 相邻方向还有图记忆的可编辑失败感知（EvoGraph-Mem）、临床推理的图自进化记忆（GSEM）等，显示该范式正在向各垂直领域扩散。

7.2 程序记忆与「经验学习」Agent

让 Agent 把成功 / 失败经验沉淀为可复用技能，是程序记忆的核心。早期里程碑包括 Reflexion（arXiv:2303.11366，语言化强化学习，把失败反思成下一轮的文字反馈）[16]、ExpeL（arXiv:2308.10144，从经验中抽取可迁移洞见与规则）[17]、Voyager（arXiv:2305.16291，Minecraft 中自动构建可增长技能库）[18]。2026 年的共识是：程序记忆长期价值最高（行为层面的复利），但在生产框架中成熟度最低，只有 Letta / LangMem 等允许 Agent 改写自身常驻指令 [26][27]。

7.3 多智能体记忆协调

当编排器 spawn 多个专业子 Agent 时，群体知识如何累积、谁拥有、冲突如何合并，目前仍多为临时方案。MemOS 的统一记忆池与 Claude Code 的子 Agent 记忆隔离都在处理这一问题；下一代框架预计会把多 Agent 记忆当作一等协调问题，引入显式归属语义与合并策略——类比分布式版本控制如何处理对共享状态的并发写 [6][26][27]。此外，来源归因（provenance） 也成为可靠性的一部分：群聊中「用户需要帮助」这句话到底是用户说的、监控 Agent 推断的、还是规划 Agent 的中间产物，必须可区分（Mem0 用消息 name 字段做 actor 归因）[26]。

7.4 隐私、安全与可删除性

记忆层是一个尚未被充分防护的新攻击面。ACL 2025 研究《Unveiling Privacy Risks in LLM Agent Memory》（arXiv:2502.13172）证明：对抗性提示可以跨会话系统性抽取存储在记忆中的个人信息，这与 prompt injection、训练数据抽取是不同的攻击面 [20]。其直接后果是：

  • 记忆库可能隐式编码个人数据，且无法在不破坏记忆连贯性的前提下被「外科手术式删除」，对欧盟 GDPR 的「被遗忘权」构成挑战；
  • 企业部署应把记忆访问按角色 / 上下文做隔离（命名空间隔离），把记忆库当作和数据库同级、需要访问控制的数据资产 [20][27]。

7.5 一个值得关注的范式之争：记忆是「被检索」还是「被重构」

2026 年出现的《Memory is Reconstructed, Not Retrieved: Graph Memory for LLM Agents》（arXiv:2606.06036）借认知科学的「记忆重构」观点，主张召回不是原样取回、而是每次基于图结构动态重构 [25]。这与 A-MEM 的记忆演化、Zep 的时序建模在哲学上相通：记忆是一个随每次读取而被重新解释、更新的活对象，而非只读日志。这可能成为下一代记忆架构的理论支点。

8. 开放问题与结论

8.1 仍未解决的难题

  1. 时间推理与陈旧度：事实演化、有效期、「as of 何时」的限定，仍是所有无时间维度系统的通病 [7][26]。
  2. 抽取误差累积 vs 检索成本：写时压缩与读时保留之间尚无两全方案，自进化记忆是最有希望的弥合方向 [22][27]。
  3. 跨会话身份与多 Agent 归属：同一用户跨设备 / 跨 Agent 的身份对齐、群体记忆的所有权与合并语义仍缺标准 [26]。
  4. 评测可信度：厂商自报分数不可直接比较，DolphinBench / STATE-Bench 等「以动作结果论英雄」的基准尚新；记忆对端到端任务结果（而非仅召回率）的因果贡献仍需更严格的度量 [26]。
  5. 程序记忆的安全性：允许 Agent 改写自身行为规则是复利来源也是风险来源——一条被污染的程序记忆可能长期、隐蔽地扭曲行为，需要沙箱、回滚与审批机制 [18][27]。
  6. 参数记忆 / 激活记忆的统一治理目前主要在自托管场景可行（MemOS），闭源 API 无法暴露 KV-Cache / 权重通路，限制了该路线的普及 [6]。

8.2 结论

智能体记忆在三年内完成了「对话历史拼接 → 独立基础设施层」的跃迁：它有了权威分类（形式 / 认知 / 动态三轴）、六代清晰可辨的架构谱系、五个专用基准、以及围绕 Mem0 / Letta / Zep / MemOS / A-MEM 的繁荣生态。对实践者，最可落地的三条建议是：把记忆当作有生命周期与治理责任的系统资源（而非一个向量库选型）；默认「提示不是事实」并定义陈旧度策略；按「事实是否随时间变化、是否需要多 Agent 共享、是否要求全程可审计」来反推架构。对研究者，自进化 / 可学习记忆、程序记忆的安全复利、多 Agent 记忆协调与隐私可删除性，是 2026 年最值得投入的四个方向。记忆，正在成为决定 Agent 能否从「一次性工具」真正走向「终身学习同事」的那块最短木板。
