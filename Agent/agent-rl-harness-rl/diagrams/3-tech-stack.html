关键技术选型建议：
• 框架：研究/灵活 → verl；生产/稳定 → Miles/Slime；Harness-Native → OpenForgeRL/Agent Lightning
• 算法：单轮数学/代码 → GRPO/DAPO/GSPO；多轮Agent → AT-GRPO/SAO + Process Reward
• 核心痛点：训推一致性（vLLM vs Train分布偏差）、长程信用分配、奖励黑客（reward hacking）、异步rollout数据staleness

📐 推荐工程 Checklist

☐ Rollout引擎与训练引擎版本对齐，定期校验 logprob 一致性
☐ 训练Harness与部署Harness共享同一代码仓库/二进制
☐ 奖励函数必须包含任务级结果信号，不只依赖verifier分数
☐ 异步Rollout设置合理的stale policy阈值（<1个epoch）
☐ 日志记录：每N步做真实Harness评测，防止reward over-optimization
☐ 保留人工评测通道，自动指标+人工双轨验证

📉 常见坑与对策

Reward Hacking：混合outcome+process奖励，定期换held-out eval
分布偏移：Harness-Native训练或引入重要性采样校正
长程信用分配：关键步骤奖励放大、失败回溯标记
工具调用格式坍缩：训练时注入错误恢复样本
训推引擎偏差：定期计算KL(训练分布||推理分布)监控
