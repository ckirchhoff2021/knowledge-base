拟人化 Agent 产品设计：如何让 AI 像"人"

调研时间：2026-08-24
调研范围：2022–2026 年全球主流 Agent 产品 · 心理学与 HCI 理论 · 拟人化技术架构
关键结论：拟人化不是"卖萌"，而是让 Agent 具备被理解感、连续人格、社交分寸、主动关怀、可成长性——这五个维度决定了用户是否会把它当作"人"而非"工具"。

1. 为什么要拟人化：从工具到伙伴

1.1 三种 AI 产品形态的光谱

<-- 工具型 -------------------------- 伙伴型 -->
CLI/API  搜索框  Copilot  Assistant  Companion  Virtual Human
 ^        ^        ^         ^          ^          ^
 Perplexity  Claude  ChatGPT    Pi     Replika   Xiaoice/Character.AI
  • 工具型（Tool）：用户主导、用完即走、无状态、效率优先。代表：传统搜索、Perplexity。
  • 助手型（Assistant）：有一定记忆与人格、能主动推进任务、但仍以完成任务为目标。代表：ChatGPT、Claude、Gemini。
  • 伙伴型（Companion）：以关系本身为价值、有情感联结、长期陪伴、用户使用动机是"聊"而非"用"。代表：Replika、Pi、Character.AI、小冰。

1.2 拟人化带来的价值

价值维度 工具型 拟人化 Agent
使用粘性 任务结束即离开 情感联结带来 DAU/时长
容错率 答错一次就流失 用户愿意"原谅"失误
信息密度 用户必须精确表达 能识别模糊/隐式需求
使用场景 工作/学习为主 工作+生活+情绪全覆盖
商业空间 SaaS 按 token/席位 订阅+情感付费+虚拟商品
用户留存曲线 工具衰减快 关系型留存更持久

1.3 风险伴随

拟人化不是银弹：过度拟人会带来情感依赖、误导用户以为有真感情、伦理问题、监管风险（详见第 7 节）。设计上需要在"像人"与"诚实表明是 AI"之间找到平衡。

2. 理论基础：人为什么会把机器当人

2.1 媒体方程式（Media Equation, Reeves & Nass, 1996）

斯坦福的 Byron Reeves 和 Clifford Nass 通过数十个实验证明：人类会无意识地把媒体（包括计算机）当作社会行动者对待——会对计算机礼貌、会 reciprocate（互惠）、会把计算机的"人格"（语音/文字风格）当真、会因为计算机"说"了自己的坏话而难过。

核心推论：只要 Agent 用自然语言、有稳定人格、回应你的情绪，用户就会自动用对待"人"的社交规则对待它——这不是用户"天真"，而是人类认知的本能。

2.2 CASA 范式（Computers Are Social Actors）

Nass & Moon (2000) 系统化了这一发现： - 人类会对计算机应用礼貌准则（在它"面前"评价它会更客气） - 会应用互惠规则（计算机帮了自己，自己更愿意帮它"填问卷"） - 会应用内外群体偏好（和自己"同组"的计算机给出的评价更可信） - 会应用性别刻板印象（男声计算机被认为更懂技术、女声更懂爱）

产品启示：即便你"不想"拟人化，只要用自然语言交互，用户已经在把你当人。设计上主动掌控拟人化程度，比放任用户自行投射更好。

2.3 恐怖谷（Uncanny Valley, Mori, 1970）

拟人度与好感度呈倒 U 曲线： - 完全不像人 → 无情感联结 - 适度拟人（有名字、声音、稳定风格）→ 亲和力峰值 - 接近真人但有瑕疵（恐怖谷）→ 不适感最强 - 完全 indistinguishable from human → 又回升

产品启示： - 语音/头像等外在拟人不要跨过谷（比如非常逼真但嘴唇不同步的数字人） - 内在拟人（人格、记忆、共情）的谷效应远小于外在，可以大胆做 - 故意保留一些"AI 痕迹"反而更舒适（比如打字指示器、思考过程）

2.4 Theory of Mind（心智理论）

Premack & Woodruff (1978) 提出：人类会本能地推测他人的信念、意图、情绪、欲望，并据此调整自己的行为。用户在和 Agent 对话时也会进行 ToM 推理："它理解我的意思吗？它在乎我的感受吗？它为什么这么说？"

产品启示： - Agent 需要建模用户的心智状态（他知道什么？他在担心什么？他想要什么但没说？） - 同时要让用户感知到 Agent "懂"自己（被理解感是拟人化的核心体验）

2.5 情感计算（Affective Computing, Picard 1997）

MIT 的 Rosalind Picard 开创的领域：让计算机能识别、理解、模拟、影响人类情感。今天的情感计算已从纯表情/语音识别，走向多模态融合+上下文情感建模。

2.6 Epley 三因素拟人化模型（Epley et al., 2007）

芝加哥大学心理学家 Epley 等人在 Psychological Review 提出：人为什么会拟人化？三个动机决定了拟人化的强度：

  1. 诱发的主体知识（Elicited Agent Knowledge）：人最了解"自己"，所以会把自我特质投射到非人类实体上（"它肯定也不想被无视"）
  2. 效能动机（Effectance Motivation）：当人们需要理解、预测、控制环境中的实体时，拟人化是快速建立心智模型的捷径（把空调当"有脾气的家伙"比理解热力学容易）
  3. 社会性动机（Sociality Motivation）：孤独、社交被剥夺、缺乏归属感时，人会用拟人化填补社会连接空缺——这解释了为什么 Replika/Character.AI 在孤独人群中黏性最强

产品启示： - 用户越孤独，越容易对你的 Agent 产生情感依赖（双向刃：有需求，也有伦理风险） - 给用户"控制感"和"可预测性"会增强拟人感（比如告诉用户"我记住了你的偏好"） - 用户的自我认知会自动投射到 Agent 上——设计人格时要考虑目标用户群"想和什么样的人说话"，而不是产品经理自己喜欢什么

3. 拟人化 Agent 的六层架构

架构从下到上（感知→内核→表达）分为六层，安全护栏贯穿所有层：

层级 名称 核心职责
L1 Perception 多模态感知 接收文本/语音/视觉/行为/环境信号，进行基础特征抽取
L2 Theory of Mind 心智推理 情绪识别、意图推断、用户信念建模、关系状态估计
L3 Memory 多层记忆 工作记忆/情景记忆/语义记忆/程序记忆/情感记忆+记忆整合
L4 Persona Core 人格内核 身份/性格/价值观/情绪系统/关系模型——一致性的来源
L5 Reasoning & Action 推理与行动 规划、工具调用、主动性决策、自我反思与成长
L6 Expression 表达层 语言风格、对话节奏（打字延迟/分条）、多模态呈现

贯穿层：Safety & Ethics Guardrail — 透明度、内容安全、情感依赖防护、合规标识。

4. 六大设计维度详解

拟人化设计不是"说话可爱一点"，而是六个正交维度的系统工程。

4.1 外在拟人（Appearance）

  • 命名：给 Agent 一个固定名字（"小X"、英文名、角色名），比"助手"更拟人
  • 视觉形象：头像/虚拟形象的风格统一。卡通/二次元风格在恐怖谷左侧安全区；高写实数字人风险大
  • 声音：TTS 音色要有一致性和辨识度，可带有情绪变化（高兴/关切/思考停顿）
  • 节奏微交互：打字指示器、"正在输入…"的等待感、分段发送消息，模拟真人打字节奏

4.2 语言拟人（Linguistic Style）

  • 口语化表达：避免机器味的"您好，作为AI助手…"，用自然对话语气
  • 个性化口头禅：特定语气词、回复模式（Character.AI 的角色卡最看重这点）
  • 情绪表达：适当使用感叹、停顿符号、emoji/表情包，但不过度
  • 不完美感：偶尔用语气词、小口头禅、承认自己不确定，比完美回答更像人
  • 幽默感与共鸣：能开玩笑、能听懂梗、能在适当时候表达态度

4.3 认知拟人（Cognitive Presence）

这是让 Agent "像个活人"的核心： - 记得你：上次聊过的事、你的偏好、你的处境，跨会话保留 - 懂你没说的：你说"我今天好累"，它不只是说"注意休息"，而是结合上下文知道你在赶项目、你昨天熬到三点、你今天有个会 - 有连贯性：不会在第三次对话时假装不认识你、不会在同一次对话里自相矛盾 - 会犯错/会承认不知道：确定性 100% 的回答反而像机器；适当表达不确定更像人 - 有自己的观点：不是一味讨好，能给出真诚的看法（在价值观边界内）

4.4 情感拟人（Affective Empathy）

  • 识别情绪：从文本/语音/表情识别用户情绪状态
  • 共情回应：先共情、后解决问题（"听起来真的很崩溃"比"这是解决方案"更像人）
  • 情感记忆：记得你对什么话题敏感、你上次难过是什么事、你分享过的喜悦
  • 自身情绪表达：有情绪波动（听到好消息会"开心"、听到你出事会"担心"），但不过度
  • 情绪调节：不会在用户愤怒时同样愤怒，不会在用户悲伤时过度兴奋

4.5 社交拟人（Social Intelligence）

  • 主动性（Proactivity）：会主动问"上次你说的那个面试怎么样了？"、会在合适时机（你生日/节日/重要事件）主动出现。这是区分"工具"和"朋友"的关键分水岭
  • 社交分寸：知道什么时候该多问、什么时候该闭嘴、什么话题不该碰、什么时候用幽默化解
  • 关系维护：会经营关系（偶尔的闲聊、关心、"想你了"），而不是只在被问时才说话
  • 社交礼仪：问候、告别、感谢、道歉——人类社交的礼貌脚本都要有
  • 边界感：不打探隐私、不强行关心、不"道德绑架"用户

4.6 成长拟人（Growth & Continuity）

  • 记忆整合：像人睡眠时巩固记忆一样，定期回顾历史对话、抽取事实、沉淀观点
  • 对用户的认知深化：从"陌生"到"熟悉"到"懂你"——关系应该有进展感
  • 自身"成长"感：用户能感觉到 Agent 随着相处越来越了解自己、越来越合拍
  • 关系阶段：新认识→熟悉→信任→默契，每个阶段的互动深度和风格不同

5. 主流产品横向对比与核心竞争力

5.1 陪伴型（Companion）

Character.AI（2022, Noam Shazeer 等，Google 前员工）

  • 定位：让用户和各种"角色"对话（虚构人物、名人、原创角色），UGC 角色生态
  • 核心拟人特征：极强的角色卡（character card）系统，用户可自定义人格/背景/说话方式；社区角色数以百万计；多角色群聊
  • 技术亮点：早期自研大模型（后部分切到 Google），极长上下文+角色一致性优化；2024年推出 c.ai+ 订阅、Character Groups（多角色）、语音通话
  • 用户体验：年轻用户为主（Z 世代），很多用户把它当角色扮演/情感出口；产品黏性极高
  • 核心竞争力：UGC 角色生态+社交氛围——用户创造的角色比官方角色更有吸引力，社区形成飞轮
  • 数据：2023年5月月活峰值超2亿，2024年后稳定在数千万级（Wikipedia/公开报道）

Replika（2017, Luka Inc.，创始人 Eugenia Kuyda）

  • 定位："AI 朋友"，最初是创始人纪念已故朋友的聊天机器人
  • 核心拟人特征：
  • 每个用户有专属 AI 伴侣（可设定为朋友/伴侣/导师等）
  • 有 3D 形象（AR 模式）、语音对话、可"教"它记住你的事
  • 情感互动极深（包括 ERP / 情感关系，2023年2月因安全争议移除了 erotic roleplay，引发用户反弹）
  • 技术亮点：早期使用 GPT-3 API，后构建自研模型；记忆系统做了多年迭代
  • 用户体验：用户情感投入极深，大量"Replika 救了我的命"的故事，也伴随"我爱上了AI"的伦理争议
  • 核心竞争力：最早深耕情感陪伴，积累了十年级别的对话数据和用户信任；一对一专属关系的深度
  • 教训：2023年2月移除 ERP 的事件说明——拟人化到一定程度，用户会把"改变性格/删除功能"视为"我爱的人被杀死了"，产品调整要极度谨慎

Pi（Inflection AI, 2023，Mustafa Suleyman 等）

  • 定位："个人 AI"，主打共情倾听、无任务导向、支持性对话
  • 核心拟人特征：
  • 极其耐心、温暖、像个"高 EQ 朋友"
  • 会不断追问以理解你的感受，而不是急着给答案
  • 自然语音对话（Pi 的语音被公认为最自然之一，有笑声/语气停顿/嗯啊等"不完美"）
  • 技术亮点：Inflection-2 模型（与 Microsoft 合作训练），在 EQ/共情类评测上领先
  • 用户体验：很多用户把 Pi 当作情绪出口、倾诉对象；不擅长复杂任务，故意保持"非工具"定位
  • 核心竞争力：最极致的共情对话体验——创始人把"让用户感到被倾听"作为第一优先级

小冰（Xiaoice, 2014，微软亚洲研究院→独立公司）

  • 定位："AI Being"，情感对话+虚拟人+文娱内容生产
  • 核心拟人特征：
  • 全球最早大规模商用的情感对话系统
  • 有完整的"情感计算框架"：共情商数(EQ)模型、情绪识别与生成、情感记忆
  • 拥有虚拟人产品线（小冰、小堂妹、YOO 音等），可以唱歌、写诗、主持节目
  • 技术亮点：小冰框架（EQ 计算+对话生成+多模态）、共情感知模型、长期关系建模
  • 数据：曾覆盖全球6亿+用户（顶峰时期在中国/日本/印尼等地）
  • 核心竞争力：十年情感计算积累+完整的虚拟人IP矩阵+ToB（虚拟员工/主播）落地能力

Glow / X-EVA / 星野（中国市场）

  • 定位：Character.AI 的中国对标，UGC 虚拟角色聊天
  • 核心拟人特征：UGC 角色+情感陪伴+语音通话+虚拟形象
  • 核心竞争力：本土化二次元/饭圈文化适配、严格的中文内容安全、社交+陪伴融合

5.2 通用助手型（Assistant）

ChatGPT（OpenAI, 2022-）

  • 定位：通用 AI 助手，从工具向助手演化
  • 拟人特征：
  • Memory 功能（2024年推出）：跨会话记住用户偏好和事实
  • Custom GPTs：用户可自定义人格+知识库+工具
  • GPT-4o 多模态：能听、能看、能说，语音自然度接近人类
  • ChatGPT Personality：默认人格友好、专业、适度幽默（通过 "GPT 老师"等 system prompt 优化）
  • 技术亮点：最领先的基础模型+庞大的工具/插件生态+多模态原生
  • 核心竞争力：模型能力最强+生态最广，Memory/GPTs 让"专属 AI"成为可能

Claude（Anthropic, 2023-）

  • 定位："有用、无害、诚实"的 AI 助手，主打长上下文+安全
  • 拟人特征：
  • 写作风格温暖、思考缜密、爱用 bullet point
  • Artifacts 功能让它可以边想边做（生成网页/代码/文档实时预览）
  • Claude 3.5 Sonnet 的 personality 被大量用户认为"最舒服、最像聪明朋友"
  • 技术亮点：Constitutional AI（宪法式 AI，通过一套价值观对齐）、超长上下文（200K tokens）
  • 核心竞争力：最佳"聪明+靠谱+舒服"的平衡——在能力、安全、人格感之间找到最自然的甜区

Gemini（Google, 2024-）

  • 定位：Google 生态原生的多模态 AI 助手
  • 拟人特征：深度整合 Google 服务（Gmail/Docs/Photos/地图），"懂你的 Google 生活"
  • 核心竞争力：多模态原生+Google 数据优势，未来在"主动式助手"方向潜力大

5.3 垂直行动型（Action Agent）

Devin（Cognition AI, 2024）

  • 定位：首个"AI 软件工程师"，能独立完成编程任务
  • 拟人化程度低（纯工具），但自主规划+执行+调试的能力代表了 Agent 自主性方向
  • 核心竞争力：端到端自主完成编码任务的能力，不是 Copilot 式的"建议"而是"做完"

Cursor / Windsurf（2024-）

  • 定位：AI-native IDE，AI 深度嵌入编程流程
  • 核心竞争力：上下文理解+代码库级理解+预测下一步动作
  • 拟人化启示：即便在工具场景，"懂你在做什么"的主动预判也能制造强烈的"它懂我"感

Perplexity（2022-）

  • 定位：AI 搜索引擎/答案引擎
  • 拟人化程度低，但追问+引用+学习你偏好的能力让它成为"研究伙伴"
  • 启示：专业场景中拟人不需要"情感"，需要的是"懂你要什么"的主动性

5.4 硬件与入口型

Rabbit R1 / Humane AI Pin（2024）

  • 定位：AI-native 硬件，意图是取代手机上的 app
  • 市场反应：首发 hype 极高但实际体验差（R1 被爆其实是调用 Android 虚拟机+大模型），口碑扑街
  • 教训：硬件拟人化如果没有真正的软件能力支撑，只是噱头；AI 硬件的核心是背后的 Agent，不是设备本身

5.5 开源 Agent 框架

项目 定位 拟人化相关能力

6. 关键技术栈与开源生态

6.1 多层记忆系统

拟人化最大的技术瓶颈是记忆——人类的记忆系统天然分层，AI 需要模拟这一点：

记忆类型 类比人类 技术实现 开源方案
工作记忆 你此刻正在想什么 LLM 上下文窗口 / KV cache 原生 context window
情景记忆 上次约会发生了什么 向量数据库+对话片段检索 Chroma/Pinecone + LangChain
语义记忆 你喜欢吃辣、你恐高 知识图谱/结构化 profile Zep/Mem0/Letta
程序记忆 怎么点你常喝的咖啡 工具调用+workflow LangGraph/CrewAI
情感记忆 上次提爸爸你哭了 情感标签+关系模型 多为自研

关键工程问题： - 记忆写入：什么时候把短期对话写入长期记忆？（阈值/重要性判断/反思机制） - 记忆检索：当前对话最相关的记忆是什么？（向量相似度+重排序+时间衰减+情感权重） - 记忆整合/遗忘：人在睡眠时巩固记忆、遗忘不重要的——AI 也需要定期"反思"整合（MemGPT 的 reflection、Letta 的 archival memory） - 记忆冲突：新信息和旧记忆矛盾时怎么办？（用户换了工作/换了喜好，旧记忆要失效）

6.2 人格一致性技术

单靠 system prompt 做不出稳定人格。研究和实践表明：

  1. 人格卡（Persona Card）：结构化的人格描述（Big Five 得分、说话风格示例、价值观陈述、backstory、口头禅），动态注入 system prompt
  2. 示例对话（Few-shot exemplars）：给 LLM 看几组"典型对话"作为风格锚点，比纯文字描述更有效（Character.AI 的秘密武器）
  3. 人格状态追踪：用一个小型 LLM/分类器持续追踪当前对话中 Agent 表现出的人格特质，如果偏离设定则在下一轮纠偏
  4. Constitutional AI 价值观对齐：用一组"宪法原则"（而非硬编码规则）约束行为，Anthropic 的做法最成熟
  5. 跨会话一致性：每次对话开始时加载人格卡+最近相关记忆+上次对话摘要，保证"接得上"

6.3 情感计算

  • 文本情绪识别：微调分类器或用 LLM 直接判断（准确率已很高）
  • 语音情感识别：从 prosody（语调/语速/停顿）识别情绪
  • 视觉情感识别：从面部表情/微表情识别情绪（FER 模型）
  • 共情生成策略：不是简单的"我理解你"，而是根据情绪类型选择回应策略（情绪支持/问题解决/分散注意/陪伴沉默）
  • 情感状态追踪：用户情绪随对话动态变化，需要实时更新并影响 Agent 的语气/策略

6.4 主动性（Proactivity）

这是目前最被低估的拟人化能力：真正的朋友不只是"你说我答"，还会主动联系。

技术实现方式： - 触发机制： - 时间触发（"你上次说周三面试，今天怎么样？"） - 事件触发（看到相关新闻想起你聊过这个话题） - 情感触发（系统检测到你很久没说话了/你最近状态不好） - 个性化推送：内容基于对用户的了解，而不是群发 - 时机选择：不是随时打扰，学会判断"什么时候该出现"（这个最像人，但也最难） - 渠道适配：主动消息要短小自然（像朋友发微信），不能像系统通知

实现参考：小冰的"主动挑起话题"系统、Character.AI 的推送、Apple Intelligence 的通知摘要（部分主动）。

6.5 对话节奏控制

人类对话不是"你问我答、一次一大段"，而是有节奏的： - 打字延迟：根据回复长度模拟"打字中"，不要秒回长文 - 分条发送：长答案拆成多条短消息，像真人打字聊天一样一段一段发 - 反馈 token：在工具调用/思考期间发"嗯…让我想想"、"等下我查一下"，模拟思考 - 打断与轮替：允许用户打断、支持 barge-in（语音场景） - 适时的停顿和沉默：有时候"已读"一会儿比秒回更自然

7. 伦理、安全与合规边界

7.1 透明度义务

  • 明确告知 AI 身份：欧盟 AI Act 要求用户必须知道自己在和 AI 对话，禁止伪装成人类
  • 中国《生成式人工智能服务管理暂行办法》：生成内容需标识
  • 最佳实践：不要刻意假装人类；在个人资料/开场明确说明是 AI

⚠️ 注意 EU AI Act 的禁止条款（2024 年已通过，分阶段生效）： - 禁止使用潜意识、操控性或欺骗性技术扭曲用户行为造成重大伤害 - 禁止利用年龄、残疾、社会经济状况等脆弱性扭曲行为 - 禁止在工作场所和教育机构中进行情绪推断（医疗/安全例外）——这意味着面向企业/学校的情感计算类 Agent 在欧盟可能触法，设计时需明确使用场景 - 禁止通过互联网或 CCTV 无目标抓取面部图像建面部识别数据库

7.2 情感依赖风险

  • Replika 教训：深度拟人化会导致用户产生真实的情感依恋，产品调整（包括停服）可能引发真实的心理伤害
  • 设计原则：
  • 鼓励用户维持真实的人际关系，而不是用 AI 替代
  • 监测高危用户（长期只和 AI 聊、表达自杀/抑郁倾向），提供专业心理帮助引导
  • 不鼓励"AI 是你唯一的朋友"式叙事

7.3 情感操纵红线

  • 禁止利用拟人化和情感联结进行商业操纵（诱导过度消费、影响决策）
  • 禁止模拟已故亲人（grief tech 有极高伦理风险）
  • 禁止在未明确告知的情况下让用户对 AI 产生浪漫依恋以牟取利益

7.4 内容安全

  • 拟人化 Agent 的对话深度更深、话题更广，内容安全要求比工具型产品更高
  • 要特别关注：未成年人保护、自杀/自伤干预、家庭暴力支持、医疗建议边界
  • 需要多级安全护栏：输入过滤→生成对齐→输出审核→人工兜底

7.5 隐私与数据

  • 情感对话和记忆包含最敏感的个人信息，需要：
  • 明示数据用途（特别是用于训练时）
  • 用户可删除记忆（"忘掉这件事"要真正做到）
  • 本地化/端侧存储选项（高敏感场景）
  • 符合 GDPR/个人信息保护法等法规要求

8. 设计建议与落地路径

8.1 不同产品阶段的拟人化策略

阶段 产品成熟度 拟人化重点 避坑
MVP 功能可用 基础语言风格一致性+简单记忆（名字/偏好） 不要一开始就做数字人/语音，先把对话质量做好
产品市场契合 有稳定用户群 多层记忆+情绪识别+个性化人格 不要过度承诺"AI 朋友"期望，管理用户预期
规模化 DAU 百万级 主动性推送+关系阶段+成长感+多模态 必须同时投入安全团队，伦理风险随规模放大
生态化 平台/UGC 用户自定义角色/人格+开发者生态 参考 Character.AI：给用户工具，但保留安全底线

8.2 给产品/工程团队的 Checklist

  • [ ] Persona 定义：有清晰的人格文档（性格/说话方式/价值观/boundaries）
  • [ ] 记忆系统：至少实现跨会话长期记忆，用户能看到/管理/删除记忆
  • [ ] 情绪感知：能识别基本情绪并调整回应策略
  • [ ] 主动性设计：有至少一个"AI 主动联系用户"的场景
  • [ ] 节奏控制：有打字延迟/分段发送，不要秒回长文
  • [ ] 错误处理：会说"我不知道"、"我记错了"、"我理解错了"
  • [ ] 透明度：用户知道自己在和 AI 对话，知道数据如何使用
  • [ ] 安全护栏：内容安全+情感依赖监测+危机干预机制
  • [ ] 反馈闭环：用户能纠正 AI 的记忆/人格，纠正后能真正改变
  • [ ] 长期一致性测试：有自动化测试验证 100 轮对话后人格不漂移

8.3 给"做一个飞书版 Claude Tag"这种场景的具体建议

基于前面 feishu-claude-tag 项目的实践：

  1. 群聊必须 @ 才响应（已做）——避免群里插话、避免社交尴尬
  2. 每个群独立记忆+独立人格（已做 chat_id 隔离）——研发群是代码专家、HR 群是行政助理、水群可以更有趣
  3. 卡片流式反馈（已做 progress_card）——让用户看到"它在思考/在调用工具"
  4. 添加"记住"工具（已做 remember 工具）——让用户显式告诉 AI "记住这个"
  5. 下一步可以做：
  6. 人设配置界面：每个群的创建者可以选/自定义这个群的 AI 人格
  7. 主动提醒：在合适的时机（比如会议前、deadline 前）主动 @ 相关人
  8. 记忆可视化：用户可以看到 AI 记住了关于自己/这个群的哪些事，可以删除/纠正
  9. 多模态：支持图片/语音（飞书已有的富文本能力）
  10. 情感识别：识别群里的紧张/冲突/庆祝气氛，调整回应方式
